# 공개 양식의 숫자·날짜·합계 입력 검증

실제 보관한 공식 원본의 인쇄 라벨·단위·행 관계를 확인하여 **10개 등록 프로파일의 92개 입력 필드와 22개 관계**에 규칙을 추가함. 이 검사는 입력값의 형식·비음수·합계·부분집합·분리 달력 날짜를 확인하는 기능임. 원자료 사실의 진위, 자격 요건, 실제 제출 허가 또는 법적 적합성을 인증하지 않음. 입력 좌표·표·서식·원본 SHA는 변경하지 않음.

HWPX는 논리적 XML 구역/표 위치이며 실제 쪽 번호를 추정하지 않음.

## 규칙 계약

필드의 `validation.type`은 `integer`, `number`, `date` 중 하나임. 일반 본문·식별자에는 숫자 파서를 자동 적용하지 않음. 적용 필드는 고정 입력 항목이므로 보고서 문장 종결 규칙을 강제하지 않음.

- 인원·건수·면적·연구비는 0 이상을 확인함. 정기보고 차수와 학년은 1 이상 정수임. 면적의 소수 자릿수나 법정 상한을 원문 없이 만들지 않음.
- 분리 신청일의 년은 1~9999, 월은 1~12, 일은 1~31 정수 범위임. 제81·82호의 같은 신청일 세 칸은 `calendar_date` 관계로 결합해 윤년·월별 말일도 검사함. 각 정수 범위를 만족하는 `2026/2/30`, `2025/2/29`도 차단하며 `2024/2/29`는 유효함. 세 칸 중 일부가 빠지면 날짜를 보충하지 않고 오류로 표시함.
- 완전한 날짜 칸은 `YYYY-MM-DD`, `YYYY.MM.DD`로 명시하고 실제 달력 날짜를 검사함. 원문에 없는 시각·일자를 보충하거나 날짜를 자동 수정하지 않음. 과거/미래 허용 조건과 법정 기한은 별도 업무 판단 대상임.
- 면적 표의 정확한 추출 표기는 `㎡`, 임상시험 인력은 `명`, 시험건수는 `건`, 정규심의 주기는 `주`임. 해당 단위가 칸 밖에 인쇄되어 `unit_location: "label"`로 선언하며 **입력은 단위 없는 숫자만** 사용함. `3명`을 입력해 기존 `명` 라벨과 중복 표시하지 않음. `㎡`와 `m²`를 자동으로 같은 문자열로 바꾸거나 단위를 환산하지 않음.
- 제81·82호 작업인원에는 별도 `명` 문자열이 인쇄되어 있지 않으므로 unit을 추정 추가하지 않음. 연구비 신청액 원칸에도 통화/단위가 없어 number만 검사함. 뒤쪽 다른 표의 천원 표시를 앞쪽 칸의 단위로 이식하지 않으며 실제 통화·단위는 작성자가 확인해야 함.
- sum은 같은 표에서 인쇄한 구성항목과 합계를 대조함. 입력자가 적은 합계를 자동 재계산하거나 덮어쓰지 않음. 교육 인원은 해당 행의 전체 인원 이하인지 확인함. IRB 위원 분류·직군·임상 단계·당해연도/진행중/종료 건수 사이에는 임의 합계 관계를 만들지 않음.

숫자 합계·대소 관계의 참조 필드는 같은 선언 단위를 사용해야 함. `calendar_date`는 같은 날짜의 year/month/day 세 정수 키를 참조함. 관계 일부만 입력하면 남은 값을 임의로 0으로 채우지 않고 보완을 요구함. 선택 필드의 빈 문자열은 원칸을 유지하며 필수 필드 빈값은 오류임. 입력 끝의 유효 출처 ID는 검사 과정에서 구분하지만 본문 중간 인용·불명확한 숫자·잘못된 쉼표·단위·날짜를 정정하지 않음.

## 이번에 제외한 해석

KOTRA XLSX의 설립년도 예시는 `2020년1월`, 출시일 예시는 `2026년5월`로 월 단위임. 이를 integer 연도 또는 완전한 date로 강제하지 않음. 정부 역사대회 생년월일 예시도 두 자리 연도와 마침표를 사용하므로 이번 완전한 날짜 3형식 계약으로 자동 확대하지 않음. 사업자/허가/등록/식별번호, 전화·계좌·서명, 제품명·함량의 복합 본문은 일반 정수·날짜로 추론하지 않음. 원문에 명확한 입력칸과 제약이 없는 비용 합계·날짜 선후·법정 만료 기간도 추가하지 않음.

규칙이 적용된 QA 값은 유효한 비제출 시험값으로 바꿈. 예를 들어 제81·82호 면적은 `12.50+8.25+3.75+5.50=30.00`, 작업인원은 `4+2+1=7`, 임상시험 인력은 전체 3/교육 2로 사용함. 실제 기업·시설·신청인·승인일에 관한 사실을 뜻하지 않으며 `demo_values`가 사용자 제출 자료를 대신하지 않음.

## API와 재현

`templates/value_rules.py`의 `validate_rule_profile(profile)`는 선언 오류를 거부하고 `inspect_form_values(values, profile)`는 문제 목록을 반환함. 문제는 `code`, `field`, `line`, `message`, `severity: "error"`를 포함함. 이 규칙은 양식 기입 전 검사와 독립 출력 검수의 입력 검증에 연결하며, 구조/폰트/원본 픽셀 보존 검사는 별도로 유지함.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest -q tests/test_registered_value_rules.py tests/test_value_rules.py
.\.venv\Scripts\python.exe -X utf8 -m pytest -q tests/test_registered_profiles.py tests/test_ra_gmp_rmp_profiles.py tests/test_ra_clinical_foreign_profiles.py tests/test_business_profiles.py
```

새 회귀는 유효 QA 값·원본 SHA/페이지 라벨/단위 근거, 음수·소수 인원·NaN·잘못된 날짜·분리 달력 오류·잘못된 합계·교육 초과·단위 중복·본문 제외, 유효 실제 기입 후 독립 검수, 오류 시 기존 출력과 원본 보존을 확인함. 윤년 날짜는 실제 제81·82호 세 칸에 기입하고 독립 검수함. corpus 원본이 없는 환경은 실제 원본 시험을 skip하며 원본을 새로 다운로드하거나 권한 제한을 우회하지 않음.

2026-10-03 집중 실행 결과는 등록 프로필 회귀 66개와 규칙 엔진 회귀 169개를 합쳐 **235 passed, 29.30초**임. 제81·82호의 `2024/2/29` 기입 출력 1쪽, 제81호 일반 QA 출력 1쪽, 제32호 1쪽, 제32호의2 1·2쪽을 PDFium PNG로 직접 확인하여 해당 입력영역의 겹침·잘림·단위 중복이 없음을 확인함. 이 시각 확인 범위를 다른 모든 양식의 전항목 검수나 실제 제출 적합성으로 확대하지 않음.

[검증 결과 JSON](../outputs/field-validation-verification.json)에 프로파일/원본 SHA와 인쇄 근거, 유효 QA 값, **92개 필드별 단일 오류·22개 관계 오류의 검출 결과**를 보관함. 보고서의 일반 QA 출력 3개와 윤년 출력 2개는 [QA 자료 폴더](../outputs/field-validation-qa/)의 실제 PDF·독립 검수 JSON·PNG와 연결하며 상대 경로 존재와 파일 SHA를 다시 대조함. 출력 5개 모두 독립 검수를 통과했고 전체 10쪽을 렌더링했음. 직접 시각 확인은 입력영역이 있는 6쪽에 한정하며 나머지 4쪽은 원본 작성영역 밖 보존을 독립 검수한 범위임. 실제 모델 호출·네트워크 호출·실제 제출은 없었음.
