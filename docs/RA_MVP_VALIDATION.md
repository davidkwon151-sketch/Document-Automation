# RA 최소 작성 흐름 검증

최초 서비스 검증은 과거 3종 스냅샷의 결과임. 품목허가 신청서(별지 4호), 품목허가·신고 갱신 신청서(별지 20호), Eurofins 공개 시료 제출 양식을 대상으로 했음. 당시 등록 텍스트 위치는 합계 37칸(원자료 기반 24칸, 직접 입력 13칸)이었으며 전체 법정·기관 제출 항목과 동일하지 않음. 현재 접수용 최신성, 허가 상태, 서명·동의·날짜·미등록 선택·첨부 요구를 자동 인증하지 않음.

`app/ra_mvp_service.py`는 등록 ID와 원본·프로파일 SHA, 기입 권한을 확인한 뒤 기존 작성·검수·다운로드 경로를 사용함. 원자료 기반 제품 정보를 사용자 직접 입력이나 보완 답변·작성 지시만으로 새로운 사실 근거로 승격하지 않음. 신청인·회사·담당자 값은 실제 사용자가 입력한 경우만 사용자 출처와 함께 보존하며, 이후 변경은 재검수 대상임. 재생성은 최초 초안의 KPI 기준·시작 시각·실행 ID를 유지하고 다른 양식의 기준을 재사용하지 않음.

최초 공개자료 기입 데모는 API 설정 없이 공식 스냅샷의 선정 원문을 복사했음. 법정 양식 2종은 한미플루 75mg의 제품명·저장방법을, Eurofins 양식은 Benepali 25mg의 제품명만 기입했음. 합계 5칸을 새로 작성하고 각각 독립 출력 검수를 수행했음. 한미 원자료의 회사 역할은 문서 발행사이며 제조원으로 추정하지 않음. 저장방법 원문에 유효기간이 없으므로 유효기간을 생성하지 않음. Eurofins 양식에 제품명을 복사하는 행위는 실제 시료나 공급 관계를 증명하지 않음. 신청인·개인정보·서명을 가짜 값으로 채우지 않음.

실제 AI 작성은 `run_pipeline(..., semantic_review=True)`에서 지시 해석 → 실제 파일 파싱·검색 → 초안 → 일반/RA 검수 → 예상 질문 → 의미·완결성 검수를 수행함. 실제 모델 호출은 기존 `llm/client.py`에서만 실행함. 정보·근거 부족과 수정 필요를 정상 보완 상태로 반환하며, 실제 API 설정·응답 실패를 데모 성공으로 대체하지 않음. 긴 원문은 기본 입력칸을 넘으면 차단함. 사용자가 별첨을 명시 허용한 PDF overlay 양식에서만 전체 근거 원문을 별첨으로 보존하며, AcroForm 입력칸에 별첨을 강제하지 않음.

```powershell
.venv/Scripts/python.exe -X utf8 -m evals.ra_mvp --mode demo --output outputs/ra-mvp/current-demo.json
.venv/Scripts/python.exe -X utf8 -m evals.ra_mvp --mode live --path "원자료.pdf" --output outputs/ra-mvp/current-live.json
.venv/Scripts/python.exe -X utf8 -m pytest -q tests/test_ra_mvp_service.py
```

최초 3종의 과거 데모 검증 결과는 `outputs/ra-mvp/demo.json`, 실제 설정 미완료 결과는 `outputs/ra-mvp/live-unavailable.json`, 실행·SHA·분모 감사는 `outputs/ra-mvp/audit.json`에 보존함. 당시 데모 3/3이 새 PDF 기입·독립 검수를 통과했고 원래 쪽수 3/1/3을 유지했음. 실제 AI 설정이 없는 실행은 0/3 성공, 3건 미평가로 분리했음. 당시 집중 테스트는 실제 M1 첨부 파싱, 주입 mock의 작성·의미 검수, 출처 없는 문장, 잘못된 수치·변경 근거, 직접 값의 사후 편집, ID·SHA·추출 권한·최초 KPI 기준 변조를 확인했음. 위 명령은 현재 카탈로그를 실행하며 최초 기록을 덮어쓰지 않도록 새 파일명을 사용함. 테스트 mock은 실제 모델 품질을 측정하지 않음.

두 번째 카탈로그 단계는 품목 변경허가 신청서(별지 8호)를 추가하여 공개 양식 4종, 등록 47칸(원자료 기반 29칸·직접 입력 18칸), 기본 선정 데모 6칸을 제공했음. 추가 양식의 등록 텍스트는 10칸이며 기본 데모는 제품명 1칸만 기입했음. 이 수치는 당시 등록·선정 범위이며 최초 3종·37칸·5칸 검증의 분모와 합산하거나 같은 스냅샷으로 표시하지 않음. 실제 변경 전후 자료, 신청 구분·서명·날짜·허가 식별자와 미등록 항목의 완료·법적 제출 적합성을 의미하지 않음.

현재 카탈로그는 임상시험계획 신청(23호)·정기 안전성정보 보고(32호)를 추가해 6종·등록80칸(근거49·직접31)·선정 데모8칸임. 원문 항목명과 대상 칸이 다르면 명시된 연결을 적용하며 원래 전체 인용·출처ID·페이지를 유지함. 신규2종의 상세표·실제 임상 지위·승인·안전성 결론과 제출 요건은 별도 확인 대상임. 최신 범위와 통합 시험은 `RA_CLINICAL_SAFETY_FORMS.md`, `RA_CLINICAL_SAFETY_VALIDATION.md`에 기록함.

별도의 후속 내부 문서 범위로 RA 내부 검토 보고서와 RA 변경 영향 검토 기안 프리셋을 제공함. 특정 회사나 기관의 공식 양식이 아닌 프로젝트 제작 예제이며, 실제 검토 원자료와 버전·관할·적용 조건, 변경 기안에는 실제 변경 전후 자료와 사유가 필요함. 작성 전에 DOCX 또는 HWPX 하나를 선택하고, 프리셋 적용 시 새 문서와 새 최초 초안 기준을 시작함. 자료에 없는 승인 완료·영향 없음·허가 필요성을 생성하지 않음.

정식 `app.ra_presets` helper를 사용하는 프리셋 2종 × 형식 2종의 mock 파이프라인 4/4 조합을 검증했음. 합성 DOCX 원자료의 실제 파싱·검색부터 mock 작성, RA·의미·완결성 검수, 새 DOCX/HWPX 기입, 저장 파일의 독립 검수·기록 재열기까지 확인함. 원본 SHA·출처 ID·정확한 시험 수치·최초 초안 기준을 대조하고, 검수 후 형식 교체와 수치 변조를 차단했음. 증거는 `outputs/ra-next-stage/formal-pipeline-audit.json`과 `formal-pipeline-artifacts/`, 사용 조건은 `docs/RA_PRESETS.md`에 기록함. 이 4조합은 공개 신청서 4종의 기입 분모에 포함하지 않음. 새 내부 예제의 실제 Word·한글 프로그램 시각 검수는 수행하지 않았음.

이 기록의 실제 API 호출·모델 응답·실사용 KPI 측정은 모두 0임. PDF 파일 구조·기입 위치·텍스트/글리프 검수와 원문 대조를 평가했으며, 전체 규제 제출 적합성이나 실제 사용자 수정 비율을 평가하지 않음. 서비스 전용 평가는 `native_review='off'`를 사용함. 화면에서 수행하는 PDF 프로그램 출력 확인은 별도 증거이며 warning·미평가를 전체 성공으로 취급하지 않음.
