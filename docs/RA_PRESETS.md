# RA 내부 검토 프리셋

공개 신청서 기입 MVP에 이어 내부 검토용 프리셋 2종을 제공함. 프로젝트에서 제작한 예제이며 특정 회사의 비공개 내부 양식이나 기관의 공식 신청서가 아님. 실제 허가·변경 승인·접수 적합성을 자동 판정하지 않음.

| 프리셋 | 작성 목적 | 내부 문서 유형 | 필요한 원자료 |
|---|---|---|---|
| RA 내부 검토 보고서 | 검토 대상·자료 버전·확인 사실·부족한 자료·후속 조치를 정리함 | 결과보고서 | 대상 제품·제형 원문, 버전·관할·검토 범위 |
| RA 변경 영향 검토 기안 | 변경 전후 상태·사유·영향 근거·추가 확인 사항을 정리함 | 품의서 | 실제 변경 전·후 자료와 각 버전, 명시된 변경 사유·대상 |

사용할 프리셋과 DOCX 또는 HWPX 형식 하나를 초안 작성 전에 선택함. 제목·요약·본문 3칸을 가진 예제를 기존 파싱·검색·작성·RA 검수 경로에 연결함. 선택한 원본 SHA와 입력 위치를 작성·출력 검수에 연결하므로, 검수한 뒤 다른 형식이나 원본으로 바꿔 바로 다운로드할 수 없음. 형식을 바꾸려면 새 문서에서 자료와 양식을 확인하고 다시 작성·검수해야 함.

실제 첨부자료를 사용하고 사실·수치마다 출처 ID를 유지함. 요약과 본문은 개조식·두괄식·`~함/~임` 종결을 적용함. 변경 전후 자료가 부족하면 실제 변경 내용, 허가 필요성, 영향 없음, 승인 완료를 만들어 쓰지 않고 추가 확인이 필요한 항목을 보여줘야 함. 담당자·일정·결재 요청도 사용자가 명시한 정보만 사용함. 검수 경고는 허가 결론이나 규제기관의 판단을 대신하지 않음.

프리셋 적용은 새 문서를 시작하는 동작임. 이전 문서의 첨부·보완 답변·양식 매핑·초안·다운로드 증거와 결재 확인 상태를 재사용하지 않음. 새 초안을 처음 보여줄 때 새 KPI 기준을 만들며, 같은 문서의 수정·재생성은 그 최초 초안 기준과 시작 시각을 유지해야 함. 예제·합성 자료 시험의 수정 비율은 실제 사용자 KPI로 집계하지 않음.

실제 AI 작성은 API 설정과 실제 원자료가 필요함. 아래 통합 회귀는 합성 DOCX 원자료와 주입 mock 응답을 사용하며 실제 API 호출·모델 평가·사람 평가가 모두 0임. 원자료를 바꾸어 허가·승인 상태를 가짜로 작성하지 않음.

```powershell
.venv/Scripts/python.exe -X utf8 -m pytest -q tests/test_ra_preset_pipeline.py
```

정식 `app.ra_presets` helper를 사용해 프리셋 2종 × 형식 2종, 총 4개 조합을 시험하여 4/4 통과함. 실제 파일 파싱 → 검색 → 초안 → RA·의미·완결성 검수 → 새 양식 기입 → 저장 파일의 독립 검수 → 기록 저장·재열기를 확인함. 원본 SHA, 출처 ID, 정확한 시험 수치, 최초 초안 기준을 대조하고 검수 후 형식 교체와 수치 변조가 차단되는지도 검사함.

산출물과 정확한 실행 결과는 `outputs/ra-next-stage/formal-pipeline-artifacts/`와 `formal-pipeline-audit.json`에 기록함. 독립 출력 검수는 DOCX/HWPX의 저장 구조·문자·서식 보존 범위이며, 이 시험의 실제 Word·한글 프로그램 렌더 및 육안 평가는 수행하지 않음. 실제 회사 양식 전수 확보, 실제 LLM 품질, 임상·규제 적합성 또는 전체 제출 완료를 의미하지 않음.
