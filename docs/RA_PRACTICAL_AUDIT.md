# RA 실제 업무 관점 독립 감사

통합 보완: 감사에서 지적한 분리된 양식/작성 경로와 선택 항목 완료 분모를 `app/ra_auto_service.py`, `app/ra_auto_ui.py`의 새 첫 탭으로 연결함. 원자료 업로드→확인 양식→선택 대상 일괄 기입/모델 작성→내용 및 저장 후 검수를 지원함. 아래 감사의 기존 작업실 판정은 구현 전 기준이며 최신 사용법은 [RA_AUTO_WORKFLOW.md](RA_AUTO_WORKFLOW.md), 최종 회귀·합성 실제 파일·API 잔액 보류는 [VALIDATION.md](VALIDATION.md)에 별도 기록함. 2026-10-05 후속으로 [CTD Module 1·3 검토용 작업 초안](CTD_WORKSPACE.md)의 절별 원문 배치·근거표를 추가했으나, 실제 모델 작성 품질·직원 KPI·법정 CTD/eCTD 제출 적합성은 여전히 미검증임.

확인일: 2026-10-04. 코드·공식 카탈로그·실제 파일 파서 경로를 대조함. RA 직원의 사용성 인터뷰, 실제 허가 제출, 실사용 수정률 측정은 이번 감사에 포함하지 않음. 다른 담당자가 병행 개발하는 새 자동작성 화면은 별도 통합 검증 전까지 완료로 판정하지 않음.

## 판정

현재 공식 양식 작업실은 **확인한 원자료를 일부 입력칸에 정확히 기입하는 도구로 사용할 수 있음**. 출처·제품·수치 대조, 원본 보존, 저장 후 같은 입력 위치의 독립 검수와 작업패키지가 실제로 연결되어 있음. 그러나 **자료와 처음 보는 양식을 올리면 작성 가능한 모든 칸을 채운 업무용 완성 초안이 나오는 기능은 보완 필요함**. RA 업무 전반을 대체하거나 모든 제약사 담당자가 반드시 사용하는 수준이라는 근거는 없음.

## 핵심 결함 5개와 최소 조치

1. **새 양식 분석과 실제 작성 기능이 주 RA 화면의 기입 흐름과 분리되어 있음.** 주 작업실은 등록 PDF의 exact-copy이고, 회사·기관 양식 업로드→AI 분석→근거 작성은 `app/ui.py`의 별도 흐름임. 사용자는 메뉴 수보다 자신의 양식에 데이터가 들어간 결과를 원함. 기존 분석·확인 매핑·pipeline·저장 후 검수를 새 RA 자동작성 탭에서 한 흐름으로 연결하는 것이 우선임.
2. **부분 기입 통과와 작업 완료의 분모가 다름.** 실제 한미플루 PDF를 공식 품목허가 전체 프로파일에 연결하면 제품명 1/16칸만 후보로 찾아지고 15칸이 비어 있어도 `ready_for_output_check=True`, 검수 오류 없음임. 이는 선택 칸 복사의 준비 상태이며 `submission_ready=False`라는 표시는 맞음. 원래 법정 필수를 추정해 전부 강제하기보다 사용자가 이번 작업에서 완성할 칸을 지정하고, 그 칸의 미기입·검수 보류와 원래 미등록칸을 별도로 표시·차단해야 함.
3. **입력 항목명과 제품 문맥을 사용자가 다시 정리해야 하는 부담이 큼.** 정확 항목명 기반 후보는 안정적이지만 일반 원자료의 다른 이름·문단·표제로는 회수율이 낮음. 실제 TXT의 `제품명: SyntheticDrugA` 다음 줄 `성상: 흰색 분말`도 각각 독립 문맥이 되어 실패했음. 이번 수정은 빈줄 경계의 원문 블록·실제 줄 범위를 보존하고, 인용 조각의 정확 offset에서 성상의 제품 범위를 검수함. 의미상 다른 항목명은 여전히 사용자 확인 매핑 또는 실제 모델 매핑이 필요함. 파일 전체에 제품명을 무조건 승계하지 않음.
4. **실제 AI 작성과 업무 효율 증거가 부족함.** 모델 호출 0회인 복사 작업의 오류 방지는 실제 모델의 초안 완성도 증명이 아님. 새로운 UI를 만든 뒤 실제 configured 백엔드의 응답으로 3개 독립 사례를 작성하고, RA 담당자가 초안→검토본을 편집하여 시간·항목별 문자 수정률·실제 반려를 측정해야 함. 잔액/API 실패를 mock 성공으로 대체하면 안 됨.
5. **검수가 보장하는 범위와 최종 제출 업무의 범위가 다름.** 내용의 규칙 검수와 저장 후 입력 위치·원본 보존 검수는 실제 연결되어 있으나 첨부파일 내용의 규제 적용성, 최신 요건, 변경 분류, eCTD 차수·기술 검증, 모든 임상 문맥·번역·오탈자 정확도를 인증하지 않음. 최종 화면에서 선택 칸 완료 / 문서 배치 검수 / 미기입·첨부·담당자 확인 / 전자 제출 확인을 나누어 보여줘야 함.

## 실제 반례와 이번 수정

인터넷 공개 실자료 반례는 기존 `data/ra_public_validation/kr/hanmi_hanmiflu.pdf`를 실제 `load_documents`→`chunk_documents`→`propose_ra_bindings`→전체 등록 `prepare_ra_workflow` 순서로 실행한 결과임. 임의 제품 사실이나 실제 신청인 정보를 추가하지 않았음. 결과: 16개 등록칸 중 제품명 1개, 나머지 15개 미기입, 문서 작성 모델 호출 0회, 준비 검수 오류 없음, 법정 제출 준비 `false`임. 이것은 한미플루 사례의 후보 회수 결과이며 다른 제품·전체 파서의 정확도 평균이 아님.

합성 TXT 반례는 임시 실제 파일을 만들어 실제 파서를 사용한 결과임. 수정 전에는 정확한 `성상` 항목도 제품 문맥 분리 때문에 `ra_field_evidence_unverified`였음. 수정 후 연속 원문 줄의 제품명·성상 후보 및 준비가 통과함. CRLF·UTF-8 BOM·CP949의 원문 문자, 빈줄 경계, 실제 줄 번호, 파일 SHA와 조각 offset을 검사함.

`parsers/extended.py`는 빈줄로 나눈 원문 블록과 `줄 2~4` 같은 실제 범위를 기록하며 전체 TXT 본문도 그대로 유지함. `agent/ra.py`의 성상 분기는 실제 조각에 있는 인용만 사용하고 검증한 원문 블록의 해당 문자 위치에서 제품 범위를 대조함. 같은 블록의 다른 제품과 같은 값, 빈줄 뒤 제품 범위 없음, 변조한 context, 조각 밖의 다른 줄 값, 인용의 인접 명시 부정 삭제를 차단함. 다른 줄의 무관한 부정은 성상에 이식하지 않음. 직접 연결된 다음 줄의 의사 판단 조건을 생략한 RA 문구도 보류되는 것을 확인함.

이 수정의 증명 범위는 선정 TXT·성상·명시 부정·직접 연결된 조건 사례임. 일반 임상 판단·모든 부정 표현·복잡한 번역·페이지 간 조건 연결의 정확성으로 일반화하지 않음. `외관` 등의 별칭을 임의 `성상`으로 매핑하지 않는 기존 경계도 유지함.

추가로 실제 TXT/DOCX 파일의 `제품명: SyntheticDrugA` 다음 줄 `제형·함량: 정제 10 mg`, `성상: 흰색 정제`, `포장단위: 30정`을 선택 제형 `정제 10 mg`에 연결해 4개 항목의 후보·준비 검수를 통과시킴. 숫자는 실제 인용 조각에서만 읽고 검증된 context offset는 제품 범위 확인에만 사용함. 고정 숫자 항목의 문맥은 확인된 양식 label과 원문 label을 대조하며, 단위를 추정·환산하지 않음. 명시 제형·함량은 같은 제품 선언 블록의 단일값만 연결함. 다음 제품·빈줄·상충 값·명시 부정은 차단하고 다른 제품의 같은 `30정`이나 용량 항목의 `30`을 포장단위에 연결하지 않음.

TXT 블록 보존에 따라 드러난 글로벌 문서 경계도 보완함. 문맥 안의 거래번호 하나만으로 같은 SHA의 다른 거래를 숨기지 않고 전체 선언을 대조하며, 같은 파일명의 서로 다른 SHA를 섞은 거래 연결은 거부함. CSV의 실제 행·열별 거래 구분은 유지함.

전용 회귀: `tests/test_ra_text_intake.py` 28개. 인접 파서·RA 후보/조건·변경 문서·글로벌 업무·멀티모달·새 RA 자동작성 서비스까지 합계 277개가 통과함. 합성 자료 기반 actual parser E2E이며 실제 모델 평가나 RA 직원 평가가 아님. 전체 회귀와 실제 UI 업로드·다운로드 검증은 통합 담당자가 별도 실행함.

## 가장 가치 있는 우선 업무

사용자의 최신 요구에 맞춰 **RA 담당자의 실제 사내외 양식 1개 + 실제 확보한 원자료 → 양식 분석·확인 매핑 → 작성 가능한 선택 칸 전체 기입 → 내용/원위치 검수 → 편집 가능한 결과·출처 기록**을 최우선으로 권고함. 대표 첫 사례는 제품 기본정보·제조/보관 자료를 사용한 사내 품목 검토/변경 검토 보고서임. 공개 설명서만으로 실제 임상시험·안전성 결론·국내 신청인·허가 상태를 만들어야 하는 사례는 첫 수락 사례로 부적합함. 법정 공식 양식은 해당 공개 원문/실제 업무 근거로 지원 가능한 부분을 별도로 다룸. 이 우선순위는 사용자 요구·현재 구현 거리 기준이며 사용 빈도 조사 결과가 아님.

새 파일 형식별 엔진을 다시 만들 필요 없이 다음 경로를 재사용할 수 있음.

1. 변환 가능한 원본을 확인한 사본으로 변환하고 `templates.compatibility.analyze_template`로 전체 입력 위치를 분석함.
2. `templates.profiles.load_form_profile`의 공식 등록과 `agent.template_learning.load_learned_profile`의 동일 SHA 확인 매핑을 우선 사용함.
3. 새 양식은 `learn_template`의 제안을 확인하고 `configure_profile` / `save_learned_profile`로 위치·규칙만 저장함. 개인 값·본문은 매핑 캐시에 저장하지 않음. PDF의 전체 페이지와 누락/실패를 확인함.
4. `collect_multimodal` / `generation_sources`에서 확인된 원자료와 실제 parse documents를 `run_pipeline`에 전달함. 제품명·제형·회사 역할·단위·문맥과 OCR 확인을 유지함. 실제 AI의 모든 요청은 `llm/client.py`를 통함.
5. `review_result`의 RA·출처·수치·의미·완결성 검수를 통과한 같은 프로파일/매핑으로 `build_downloads`를 실행하고 원위치 검수와 출처 기록을 제공함.

## 실사용 수락 기준

| 확인 항목 | 통과 조건 |
|---|---|
| 실제 업무 3건 | 서로 다른 회사/양식/제품 자료의 사용 권한 있는 3건. 합성 사례와 공개원문 복사 사례는 별도 표시함. |
| 전체 작업 분모 | 이번에 작성할 선택칸, 기입칸, 자료 부족칸, 직접 입력칸, 미등록칸·첨부 미확인을 각각 표시함. 선정 필수칸이 빈 상태면 '작업 완료'나 최종본 다운로드로 표시하지 않음. |
| 새 양식 흐름 | 파일 업로드→확인 매핑→한 번의 작성→검수/최종 확인으로 접근 가능함. 작성 가능한 칸마다 출처 dropdown·복사 textarea를 강요하지 않음. 필요 질문은 한 번에 최대 2개임. 실제 클릭/입력 수와 사용자 CSV 사전 정리 시간을 기록함. |
| 원자료 위치 | 모든 자동 기입 사실·숫자에 파일 SHA·실제 페이지/시트/줄 범위·전체 인용·정확 위치가 있음. 다른 제품·행·역할·단위·기간·부정/예외의 근거로 바꿔 연결한 반례를 보류함. |
| 실제 AI 작성 | configured 유료/local 백엔드의 실제 요청·응답·오류 수를 기록함. API 실패를 rules-copy/mock 완료로 바꾸지 않음. 모델이 초안을 생성한 결과와 원문 복사를 구분함. |
| 이중 검수 | 내용 검수 및 저장 후 실제 원본 동일 위치·서식·전체 페이지·기입값/줄바꿈 검수가 각각 증거로 남음. UI 수정·자료·매핑·양식 SHA 변경 시 이전 검수와 결과를 지움. |
| 결과 사용 | 원본을 덮어쓰지 않고 업로드 양식의 지원 형식 또는 명시한 변환 형식으로 다운로드함. 변환·배치·수식 재계산의 미검증 범위를 표시하고 서명/승인/동의를 만들지 않음. |
| KPI | 실제 모델 초안을 처음 표시한 시각/내용을 고정하고 최종 확인까지 시간, 항목별 문자 편집 거리/비교 길이, 실제 상사 반려·재작업만 기록함. 자동 제안·복사 결과에 수정률 0%를 붙이지 않음. 목표치는 실제 직원 파일럿 기준과 함께 합의함. |

## 공식 자료 확인과 해석 한계

식약처의 [2026-05-18 eCTD v4.0 설명회 자료](https://staticnedrug.mfds.go.kr/resources/26%EB%85%84%20eCTD%20v4.0%20%EC%84%A4%EB%AA%85%ED%9A%8C%EC%9E%90%EB%A3%8C%28260518%29.pdf)는 CTD 내용 표준화와 eCTD의 파일·폴더·XML 등 전자 제출 구조를 구분하고, 신규/보완/재제출을 포함한 전체 절차와 제출구조 검증·차수 관리를 설명함(PDF 5, 15, 53~59쪽). 이 근거로 일반 양식 기입과 출처 ZIP을 eCTD 제출 완료로 안내하면 안 된다고 판단함. 2026-05 자료이며 2026-10 현재의 모든 품목별 최신 접수 요건을 확인했다는 뜻은 아님.

식약처 공식 [2023 바이오의약품 다빈도 보완사례 안내](https://ltfu.mfds.go.kr/bbs/164/Detail.do?bbscttNo=6391)는 허가항목과 제출자료 분야의 주요 보완사례를 구분함. 이는 참고할 과거 안내서의 존재 근거이며 이번 도구가 해당 보완 사항을 전부 판정한다는 근거는 아님. 품목갱신/ICSR 안내서 일부 기존 링크는 이번 웹 열람에서 실패해 최신 내용 확인 근거로 사용하지 않음. 새로운 공식 양식 원본의 대량 수집은 수행하지 않았음.
