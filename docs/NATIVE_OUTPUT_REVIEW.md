# 실제 문서 프로그램 출력 확인

저장 후 독립 검수에 실제 인쇄 결과 검사를 추가함. 원본과 기입본을 같은 프로그램으로 PDF 출력하여 문구의 추가 인쇄, 전체 페이지 글자 경계와 Excel 셀의 표시·숨김·인쇄 영역을 검사함. 원본 입력 위치·서식·출처·수치 검수는 먼저 실행하며 두 검수 결과를 별도로 보관함.

## 사용 방법

Streamlit 다운로드 영역의 **실제 문서 프로그램 출력 확인**은 기본으로 켜져 있음. Word·Excel·PowerPoint가 설치되어 있고 안전하게 별도 인스턴스를 사용할 수 있을 때 실행함. 확인 결과의 프로그램·쪽수·문제와 미리보기 PDF를 표시하며 쪽 번호로 전체 페이지를 확인할 수 있음.

**출력 확인이 완료되어야 다운로드**를 선택하면 요청한 모든 형식의 추가 검수가 `passed`일 때만 파일을 준비함. 경고나 미평가 형식이 하나라도 있으면 일부 형식만 성공으로 내려주지 않음. 기본 자동 모드에서는 명확한 누락·숨김·인쇄 영역 제외·새 경계 넘침을 차단하고, 확인할 수 없는 형식이나 애매한 항목은 경고를 함께 표시함.

API는 기존 호출의 호환성을 위해 기본 `native_review='off'`를 유지함.

```python
outputs = build_downloads(result, confirmed=True, native_review='auto')
reports = result['native_output_verification']
# 미리보기 PDF는 세션용 result['_native_preview_bytes']에 있음.
```

| 모드 | 추가 확인 | 다운로드 조건 |
| --- | --- | --- |
| `off` | 실행하지 않음 | 기존 출처·수치·양식·독립 위치 검수 통과 |
| `auto` | 실행 가능한 형식 확인 | 명확한 출력 오류는 차단하고 경고·미평가는 표시 |
| `required` | 요청한 모든 형식 확인 | 모든 형식의 추가 확인 통과 |

## 검수와 보존 범위

- 원본의 제목·예시에도 같은 문구가 있는 경우 원본 출력의 등장 횟수를 제외함. 전역 자리표시자 하나가 여러 물리적 입력 위치에 있으면 실제 위치 수만큼 추가 인쇄를 요구함.
- Excel의 `.Text`, 숫자 표시 형식, 행·열·시트 숨김 및 명시적 인쇄 영역을 실제 프로그램에서 읽음. 짧은 숫자·선택 표시·공통 문구의 정확한 PDF 위치를 이 검사만으로 인증하지 않으며 미평가 분모를 별도로 기록함.
- PDF 모든 페이지의 글자 경계를 순차 판독함. 원본에도 있는 경계 문제와 기입 후 새 문제를 구분함. 전체 표 높이·이미지 겹침·모든 글꼴의 시각 품질을 인증하는 검사는 아님.
- 원래 잘린 글자가 페이지·좌표만 이동하고 잘린 문자 수가 늘지 않으면 경고로 남김. 같은 글자 빈도가 새 입력의 잘림을 가리지 않도록 선택값의 경계 밖 등장 횟수도 별도로 대조함. 문자 인덱스 연결을 입증할 수 없으면 미평가로 표시함.
- 원본을 덮어쓰지 않고 읽기용 사본을 열며 글꼴·배율·인쇄 영역을 자동으로 바꾸지 않음. 안전상 확인할 수 없는 보호·서명·실행 요소의 추가 미리보기만 보류함. 기존 작성 권한·독립 검수는 완화하지 않음.
- Office 프로세스의 새 PID·시작 시각·프로세스명·자동화 실행·빈 문서 컬렉션을 확인한 뒤 사용함. 기존 사용자 인스턴스를 변경하거나 종료하지 않으며 시간 초과 종료도 소유권을 재대조함.
- HWP/HWPX의 한글 네이티브 배치는 아직 미평가임. LibreOffice는 이 환경에 없으며 설치 여부를 성공으로 대신 표시하지 않음.
- 초안·근거·원지시·보완 답변·매핑·검수·출력 모드·원본 SHA가 바뀌면 이전 파일과 미리보기를 제거함. 미리보기 바이트는 보고서 JSON에 저장하지 않고 검수 SHA·쪽수·분모만 보존함. 최초 초안 KPI 기준과 사용자 반려·재작업 횟수는 변경하지 않음.
- 여러 형식의 순차 검수에서도 마지막 파일 공개 직전에 모든 원본 SHA를 다시 대조함. UI의 현재 원본 SHA와 각 출력 검수의 원본 SHA를 연결하여, 앞선 형식의 검수 후 원본 변경으로 오래된 파일이 다시 유효해지는 것을 막음.

## RA 평가 재실행

공식 공개 원자료를 원문 복사 규칙으로 대조하는 평가임. 실제 모델 생성 품질이나 담당자 수정 비율 평가가 아님. 아래 명령은 각 입력 위치의 독립 검수와 추가 PDF 검수를 함께 실행하고 결과·출처 sidecar·미리보기 PDF를 남김.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m evals.ra_public --mode rules --native-review auto --profile ra_law_form_4_pdf --profile ra_law_form_20_pdf --profile corporate_roche_supplier_change_request --output outputs/ra-native-ema.json --artifact-dir outputs/ra-native-ema
.\.venv\Scripts\python.exe -X utf8 -m evals.ra_public --mode rules --native-review auto --manifest evals/ra_korean_sources.json --output outputs/ra-native-korean.json --artifact-dir outputs/ra-native-korean
```

`--native-review required`에서는 별첨 등 추가 검사 범위에 남는 경고도 성공으로 집계하지 않음. 서로 다른 native 모드의 결과를 같은 baseline으로 비교하지 않으며 이전 기록의 모드 누락은 `off`로 해석함.

공개 자료의 회사 역할·제품 제형·관할·전체 인용·페이지·SHA를 유지함. 해외 판매허가권자를 국내 신청인으로 바꾸지 않으며 신청인·서명·기관 요구 첨부는 임의 완성하지 않음. 평가 범위와 회사별 양식 보류 상태는 [실자료 기록](RA_REAL_SOURCE_VALIDATION.md)에 구분함.

## 실제 출력 확인 기록 — 2026-10-03

실제 설치된 Office에서 공개 양식 기반 준비본·기입본과 합성 비용 양식 6사례를 비교함. DOCX 2사례·XLSX 3사례·Bosch PPTX 1사례에서 원위치 구조 검수는 6/6 통과함. 추가 출력 검수는 PPTX 1사례 통과·나머지 5사례 경고임. 짧은 QA 문자열·숫자 표기·불명확한 인쇄 영역의 미평가 분모와 Excel 계산 대기 상태를 성공으로 바꾸지 않음. 원본과 기입본 PDF는 합계 92쪽임.

Word 숨김 글자, Excel 숨김 행·숨김 열·인쇄 영역 밖 기입의 고의 오류 4사례는 원위치 XML 검수를 통과해도 실제 출력 검수에서 모두 차단함. 정상 대조 2사례는 통과함. Word의 눈에 보이는 제목에 같은 값이 있어도 새 입력이 인쇄되지 않으면 실패함. 이 대조 PDF는 원본·기입본 합계 12쪽임.

합계 **104쪽을 렌더링하고 12개 비교 몽타주를 직접 확인했으며 선택 18쪽을 확대 확인함**. 나머지 쪽은 몽타주 수준의 확인임. 공개 MSS/KOTRA Excel의 원래 열 방향 페이지 분할·제목 잘림은 그대로 경고로 기록하며 원본의 배율·폰트·인쇄 영역을 변경하지 않음. [확인한 파일·쪽·해시·판정](../outputs/native-product/visual-qa.json)에 범위를 구분함. 이는 모든 문서의 완벽한 배치를 인증한 결과가 아님.

별도 실제 Excel 계산 진단에서 비용 양식 1개·고유 수식 6개를 18개 단계로 반복 대조하여 108/108개 확인값이 정답과 일치함. `CalculationState=2`가 계속 남아 전체 재계산 완료는 미확인임. 제품 검수는 `native_calculation_pending` 경고와 `formula_recalculated=false`를 유지함. [계산 진단](../outputs/native-product/excel-calculation-qa/summary.json)에 원본·사본 SHA와 단계별 값을 기록함. 108개를 서로 다른 수식 수로 세지 않음.

실제 `build_downloads`에서도 Word 6개 선택 필드의 추가 인쇄 검수를 통과함. HWPX 미평가가 함께 있는 자동 모드와 모든 형식 통과가 필요한 필수 모드를 대조하여, 필수 모드에서 부분 파일·이전 검수 증거·미리보기 공개가 차단됨을 확인함. 미리보기 바이트를 저장 JSON에서 제외하며 최초 KPI 기준을 유지함. [통합 기록](../outputs/native-product/live-pipeline/summary.json)은 합성 오프라인 초안이며 실제 모델 호출은 0회임.

위 통합 호출은 최종 다형식 SHA 보강 후 실제 Word로 재실행하고 별도의 미리보기 1쪽을 직접 확인함. 글꼴·표·제목·본문·출처의 선택 입력을 확인했으며, 앞의 104쪽 비교 묶음에 이 1쪽을 합산하지 않음.

평가의 각 실행은 새 UUID 하위 경로에 출력·sidecar·미리보기를 저장함. 성공→실패→재성공을 순서대로 실행해 이전 파일이 현재 실패 증거로 표시되지 않는지 검사함. 긴 회사명·제품명 사례가 Windows 경로 한도를 넘던 문제도 실행 폴더 이름 중복을 제거하여 보강함. 실패 이력과 수정 후 재실행을 별도 보존함.
