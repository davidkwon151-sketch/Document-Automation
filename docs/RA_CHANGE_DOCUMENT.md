# RA 변경 원자료 → 공식 변경 신청서

RA 문서 작업실의 **공식 변경 신청서 작성** 화면은 실제 원자료 두 버전에서
담당자가 확인한 차이를 식약처 별지 제8호 원본의 고정 3행에 연결함.
새 회사·기관 양식을 확보한 수로 집계하지 않으며 등록된 기존 공식 원본을 재사용함.

1. 제품명과 제형·함량을 원문 그대로 입력하고 변경 전/후 원자료를 각각 첨부함.
2. 원문과 같은 항목명으로 비교함. `항목명: 값`의 명시 항목을 사용함.
   사진·스캔 전사문은 원본 전체 대조 확인 후 사용하며 보류 자료가 있으면 작성하지 않음.
3. 문자 차이가 있는 항목 최대 3개를 선택함. 같은 값·자료 없음·모호한 항목을 변경 행으로 승격하지 않음.
4. 실제 변경 사유를 담당자가 직접 작성하거나 제품·제형/함량이 명시된 사유 자료의 정확한 원문을 선택함.
   사유를 생성하거나 승인·임상 판단을 추정하지 않음.
5. 선택한 각 변경 항목의 제품·함량·조건·버전·사유를 확인하고 준비 검수를 실행함.
6. 출력 확인 후 PDF 원위치 기입과 저장 후 독립 검수를 실행함.
   결과 PDF, 전체 출처 JSON, 변경 비교 CSV, 미기입칸·첨부 확인 목록이 있는 작업 ZIP을 다운로드함.

변경 사유를 직접 작성한 칸만 이번 작업의 사용자 입력으로 선언함.
양식 원본·등록 카탈로그·글꼴·표·입력 위치·분량 제한과 원본 관계 규칙을 변경하지 않음.
사용한 행은 항목/전/후/사유 네 칸을 모두 확인하며 사용하지 않은 행은 비워 둠.
행 한도를 넘거나 길이가 넘치는 내용을 자르거나 임의로 별첨 처리하지 않음.
신청인·제조소·연락처·품목허가번호는 본인이 확인한 값만 직접 입력함.

## 구현 API

- `agent.ra_change_document.prepare_ra_change_document(profile, before_sources, after_sources, ...)`
  원자료·확인 항목·사유를 재대조하고 기존 `prepare_ra_workflow` 검수 결과를 반환함.
  같은 원자료 ID가 두 버전에서 쓰였으면 별칭으로 분리하고 원래 전체 레코드를 보존함.
  이미지/전사 확인 지문도 별칭 변경 전에 다시 검수함.
- `agent.ra_change_document.export_ra_change_document(entry, result, ...)`
  공식 원본/프로파일 SHA를 다시 확인하고 원래 입력에서 준비 결과 전체를 재생성하여 대조함.
  기존 양식 기입·독립 저장 후 검수·작업패키지 SHA 검수를 사용함.
- `app.ra_change_document_ui.render_change_document()`
  기존 RA 작업실 탭에서 실행하며 공통 멀티모달 업로드를 사용함.

## 검증과 제한

`tests/test_ra_change_document.py`, `tests/test_ra_change_document_ui.py`에서
사유 누락·길이 초과·3행 한도·타제품·모호한 인용·원문 항목 없음·확인 지문 변조·이전 다운로드 재사용을 검증함.
공식 공개 PDF 원본에 합성 원자료와 합성 사용자 사유를 실제 기입하는 시험도 포함함.

이 흐름은 원문 기반 자동 비교·기입임. 실제 LLM 초안 작성 정확도나 실제 직원의 수정률을 평가한 결과가 아님.
법정 전체 필수항목·최신 접수 가능 여부·선택/서명·첨부 내용·변경 승인·전자 제출 적합성은 별도 확인해야 함.
반복 행을 동적으로 늘리는 기능과 기존 허가사항에서 변경 사유를 임의 추론하는 기능은 제공하지 않음.
