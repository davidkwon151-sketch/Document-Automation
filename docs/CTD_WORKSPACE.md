# CTD Module 1·3 자료 기반 작업 초안

이 화면은 제네릭·개량신약 담당자가 가진 행정·품질 원자료를 **절별 작업 초안과 근거표**로 정리하는 도구임. 식약처 제출용 CTD/eCTD 패키지, 법정 첨부 목록의 자동 판정, 허가 신청·승인 기능은 아님.

## 사용 순서

외부 담당자는 [공유 작업실](https://ra-document-workspace-20261004.sooyeon-jun-0389.chatgpt.site/workspace)에 개인 초대로 입장하거나 로그인한 뒤 양식·원자료를 업로드할 수 있음. 화면 아래 **CTD Module 1·3 원문 기입 작업**에서 같은 절 선택·원문 미리보기·확인 후 DOCX/HWPX 사본 다운로드를 수행함. 자기 Claude 계정의 커넥터 연결과 `ra_ctd_preview` 사용법은 [개인 Claude 연결 안내](CLAUDE_MCP.md)에 있음. 외부 시험 배포는 현재 PC와 임시 터널이 실행 중일 때만 처리 가능함.

먼저 합성 예제를 시험하려면 제품명 `예시정`, 제품 구분 `정제 5 mg`, 절 `3.2.P.3.2`·`3.2.P.5.4`·`3.2.P.8.3`을 선택함. [배치 처방](../samples/ctd_demo_batch_formula.txt), [배치 분석](../samples/ctd_demo_batch_analysis.txt), [안정성 자료](../samples/ctd_demo_stability.txt)를 원자료로 업로드하고, [작업 양식](../samples/ctd_demo_template.docx)을 선택하면 기입본과 근거 JSON을 내려받을 수 있음. 이 네 파일은 프로젝트 제작 합성 예제이며 실제 RA 제출·시험 데이터가 아님.

1. `app/ra_workflow_ui.py`의 **CTD Module 1·3** 탭에서 제품명과 실제 제형·함량 등 제품 구분값, 작성할 절을 선택함.
2. 기존·신규 자료를 첨부함. 공통 입력 경로는 PDF, DOCX, HWP/HWPX, XLSX, TXT/CSV/TSV, PPTX, PNG/JPEG를 받음. 사진·스캔의 OCR/전사문은 원본 페이지와 전문을 대조해 확인한 뒤에만 근거로 사용함.
3. 절별 초안·근거 ID·파일 SHA·원문 위치와 **부족/모호/보류** 목록을 확인함. 서로 다른 제품·함량·시점의 값을 합치거나 빠진 시험값·허가정보·신청인·서명을 만들지 않음.
4. 담당자가 실제 원문과 적용 범위를 확인한 뒤 작업용 DOCX와 근거 JSON을 내려받음. 원자료와 신청 유형에 맞는 현행 식약처 요구사항, 법정 첨부, 전자 제출 구조는 별도로 확인함.

사내 CTD 작업 양식이 DOCX/HWPX이고 절마다 `{{3.2.P.5.4}}`, `{{3.2.P.8.3}}`처럼 **등록된 CTD 절 ID의 고유 자리표시자**가 있다면, 해당 절의 확인 대기 초안을 양식 사본에 기입할 수 있음. 양식에 없는 절은 근거표에 누락/모호 현황을 남기며, 양식에 있는 절에 근거가 없거나 서로 충돌하면 기입본 다운로드를 보류함. 신청인·서명·선택 칸과 반복 위치의 자리표시자는 자동 기입하지 않음. 문서에는 실제 원문만 인쇄하고 출처 ID·원문·SHA·페이지/시트는 별도 JSON에 보존함. 한글 바이너리 HWP 양식은 기존 안전한 HWP→HWPX 변환 후 사용함.

시작할 때는 실제 보유한 **품목허가·신고 신청 자료, 표시기재, 원료 규격/시험 자료, 배치 처방·제조기록, 배치별 시험성적서(CoA), 안정성 표·보고서**를 올리면 됨. 서로 다른 원료·완제, 함량·제형, 배치·시험 시점은 같은 값으로 합치지 않음. 원료의약품 문서의 이름이 완제 제품명과 다르면, 실제 원료명 인용·파일 SHA를 확인하여 해당 완제와의 관계를 담당자가 연결한 뒤에만 3.2.S 절 후보로 사용함. 이 연결은 담당자 판단 기록이며 원문만으로 원료–완제 관계가 증명됐다는 뜻이 아님. 자료에 CTD 절 제목이 없다면 담당자가 출처 ID와 원문을 보고 절을 연결하거나, 명시적으로 모델 절 분류를 요청한 뒤 제안을 확인할 수 있음. 분류 모델은 **출처 ID→절 ID**만 제안하며 원문 수치나 사실을 새로 작성하지 않음. 유료 API 잔액이 없더라도 명시적인 절 제목/직접 확인 매핑을 이용한 원문 배치는 가능함.

ICH [CTD 개요](https://www.ich.org/page/ctd)는 Module 1을 지역별 행정 정보, Module 3을 품질 자료로 구분함. [M4Q(R1) 품질 목차](https://database.ich.org/sites/default/files/M4Q_R1_Guideline.pdf)의 3.2.S와 3.2.P는 이 작업 화면의 절 분류 근거임. 특히 3.2.P.3.2 배치 처방, 3.2.P.5.4 배치 분석, 3.2.P.8.3 안정성 자료는 서로 다른 배치·시험조건·시점을 임의로 합치면 안 됨. 식약처 [CTD 해설서(2020)](https://www.mfds.go.kr/brd/m_1060/view.do?seq=14672)와 [제네릭 CTD 질의응답집(2024)](https://mfds.go.kr/brd/m_1060/view.do?seq=15522)은 업무 참고자료임. 국내 세부 제출 요건은 [식약처 고시 제2026-65호](https://www.law.go.kr/admRulLsInfoP.do?admRulSeq=2100000284794)와 해당 별표 및 신청 유형별 최신 안내를 담당자가 대조해야 함. 이 고시 제6조는 CTD 작성 대상과 신청인이 선택 가능한 품목을 구분함. 화면의 Module 1 하위 작업 이름은 정리용이며 공식 별지·절 번호로 주장하지 않음.

**검증 분모:** 선택한 절 중 제공된 원자료에서 명확한 원문을 연결한 절의 수, 부족·모호·보류 절의 수를 셈. 이를 법정 필수 절·첨부의 전체 분모로 사용하지 않음. 현재 기능은 원문 추출·배치이며 실제 LLM 생성, 사람 수정 비율, eCTD 기술 검증을 통과했다고 표시하지 않음.
