# RA 대표 양식 최소 MVP와 후속 확장

대표 공개 양식 3종으로 1차 로컬 MVP를 완료한 뒤 현재 고유 공개 원본 6종을 제공함. 별지23·32의 앞·뒤쪽 작성 설정을 추가해 선택 메뉴는 8개, 고유 입력 위치는 84개임. 원자료 확인, 초안 생성, 수정·재검수, PDF 및 출처 기록 다운로드를 수행함. 새 입력 위치와 원자료 조건은 [앞·뒤쪽 작성 안내](RA_SECOND_PAGE.md)에 기록함.

## 실행

Python 3.11 환경과 requirements.txt 설치 후 프로젝트 폴더에서 실행함.

```powershell
./start_ra_mvp.ps1
```

PowerShell 스크립트를 실행할 수 없는 환경에서는 실행 정책을 바꾸지 않고 아래 명령을 사용함.

```powershell
.venv/Scripts/python.exe -X utf8 -m streamlit run app/ra_mvp_ui.py --server.address 127.0.0.1 --server.port 8502
```

화면 주소는 `http://127.0.0.1:8502/`임. 기존 다양한 양식의 분석·매핑 화면은 `app/ui.py`, 기본 포트 8501에서 사용함. 서버는 이 컴퓨터에서 실행하며 관공서나 기업에 서류를 전송하지 않음.

## 두 가지 작성 모드

**공개자료 기입 데모:** API 키 없이 제공된 공식 원자료 스냅샷의 선정 항목을 복사·검수함. 작성 지시나 새 첨부를 적용한 AI 초안 생성으로 표시하지 않음. 품목허가·갱신 양식은 한미플루 75mg 제품명과 저장방법, Eurofins 양식은 Benepali 25mg 제품명을 작성함. 변경허가·임상시험계획 신청·정기 안전성정보 보고는 제품명만 작성함. 선정 사실 기입은 합계 8칸이며 확인되지 않은 항목은 비워 둠. 제품명 복사를 실제 시험약 지위·임상시험 승인·실시·안전성 평가나 제출 관계의 증거로 표시하지 않음.

**실제 AI 작성:** 프로젝트 `.env`의 OpenAI 설정 또는 명시적 `LLM_PROVIDER=local`을 사용함. API 잔액 없는 실제 작성은 로컬 서버·작성 모델·임베딩 모델이 필요하며 [로컬 AI 안내](LOCAL_AI.md)를 따라 준비함. 현재 연결의 mock 검증과 실제 로컬 추론/품질 평가는 구분함. 실제 업무 지시와 PDF/DOCX/HWPX/XLSX/TXT/CSV 원자료를 입력하고, 신청인·회사·담당자 정보는 직접 입력함. 모든 모델 요청은 `llm/client.py`에서 실행함. 부족한 정보는 한 번에 최대 2개 질문으로 보완하며 답변을 누적함. 제품 사실·수치에 대한 작성 지시만으로 원자료 증거를 대신하지 않음.

## 사용과 검수

1. 양식을 선택하고 작성 모드·지시·원자료·직접 정보를 입력함.
2. 초안의 빈 항목과 원자료 출처를 확인함. 남은 빈칸·서명·선택·첨부 요구는 제출 담당자가 별도로 확인함.
3. 수정한 내용은 `수정본 다시 검수`로 출처·수치·RA 조건·완결성을 확인함. 오류가 남으면 파일 준비를 차단함.
4. 초안과 원자료를 확인한 뒤 `양식 파일 준비`를 누름. 원본 양식의 SHA·입력 위치·페이지·비입력 영역과 저장된 값을 독립 대조함.
5. PDF와 출처·검수 JSON을 각각 내려받음. 입력·자료·양식·매핑이 달라지면 이전 다운로드와 검수 증거를 제거하고 다시 작성함.

긴 원문은 기본적으로 입력칸을 넘으면 차단함. PDF 좌표 입력에서 사용자가 별첨을 명시 허용한 경우에만 원문 전체와 출처를 별첨에 보존함. 별첨 허용 선택은 기관의 법정 첨부 요건 확인을 대신하지 않음.

## 이번 범위

| 양식 | 등록 텍스트 입력 위치 | 데모 원자료 기입 |
| --- | ---: | --- |
| 의약품 품목허가 신청서, 별지 4호 | 16 | 제품명·저장방법 2칸 |
| 품목허가·신고 갱신 신청서, 별지 20호 | 16 | 제품명·저장방법 2칸 |
| Eurofins 공개 시료 제출 양식 | 5 | 제품명 1칸 |
| 의약품 품목 변경허가 신청서, 별지 8호 | 10 | 제품명 1칸 |
| 임상시험계획 승인(변경승인) 신청서, 별지 23호 | 19 | 시험약 제품명 칸에 제품명 원문 1칸 |
| 임상시험용의약품 정기 최신 안전성정보 보고서, 별지 32호 | 14 | 제품명/성분명 칸에 제품명 원문 1칸 |

위 표는 첫 쪽 설정의 합계 80칸(원자료 기반49·직접 입력31)임. 새 앞·뒤쪽 설정은 23호의 시험 목적·투여 방법과 32호의 서론·일련 목록 및 요약표 데이터 4칸을 추가함. 고유 입력 위치는84칸(근거53·직접31)이며 중복 설정의 등록 작업 수117개와 구분함. 최초 MVP는3종·37칸·선정 데모5칸, 이후4종 단계는47칸·선정 데모6칸이었음. 이는 전체 입력·선택·서명·첨부의 완료 수가 아님. 접수 가능한 최신 버전·국내 허가·실제 시료 제출 관계·규제 적합성을 자동 인증하지 않음.

임상시험 양식은 신청서, 안전성정보 양식은 보고서로 처리하고 각 업무에 맞는 초기 지시를 제공함. 원문 `제품명`과 대상 칸 `시험약 제품명`/`제품명 성분명`의 명시된 연결은 전체 원문과 원래 출처 ID·페이지를 보존하며 새로운 사실 근거를 만들지 않음. 자세한 등록 범위는 `RA_CLINICAL_SAFETY_FORMS.md`에 기록함.

## RA 내부 보고서·기안 예제

기존 확장 화면 `http://127.0.0.1:8501/`의 `RA 내부 검토 예제`에서 내부 검토 보고서 또는 변경 영향 검토 기안을 고름. DOCX/HWPX 형식을 작성 전에 선택하고 `예제로 새 문서 시작`을 누름. 이전 초안·답변·첨부·KPI 기준을 새 문서에 섞지 않음. 프로젝트 제작 예제이며 실제 회사나 기관의 공식 양식으로 표시하지 않음.

원자료·변경 전후 자료와 버전을 첨부해야 함. 자료가 없으면 실제 변경 이력·영향 없음·허가 필요성·승인 완료를 만들어 작성하지 않음. 기존 RA 전문 프롬프트와 이중 검수, 원본 보존·저장 후 독립 검수를 재사용함. 자세한 사용법과 시험 범위는 `RA_PRESETS.md`에 기록함.

## 수정 KPI

같은 문서를 보완·재생성해도 최초 사용자 표시 초안과 시작 시각을 유지함. 양식·모드를 바꾸거나 `새 문서 시작`을 누르면 새 문서로 구분함. 수정 비율은 항목별 문자 편집 거리로 계산하며, 실제 반려와 재작업은 사용자가 기록한 횟수만 세음.

확인 기록은 `data/ra_mvp/demo_runs/`와 `data/ra_mvp/live_runs/`로 구분함. 데모의 수정률과 내부 자동 수정은 실사용 AI KPI로 합산하지 않음. 이번 소프트웨어 검증의 실제 모델 응답·사람 KPI 관측은 0건임.

## 검증 명령

```powershell
.venv/Scripts/python.exe -X utf8 -m pytest -q
.venv/Scripts/python.exe -X utf8 -m evals.ra_mvp --mode demo --output outputs/ra-mvp/demo.json
.venv/Scripts/python.exe -X utf8 -m evals.ra_mvp --mode live --path "제품 원자료.pdf" --output outputs/ra-mvp/live.json
```

실제 AI 설정 오류·정보 부족·근거 부족은 성공으로 집계하지 않음. 시험 중 주입한 mock 응답도 실제 모델 품질 평가가 아님. 서비스 검증은 `RA_MVP_VALIDATION.md`, 양식과 원본 범위는 `RA_MVP_FORMS.md`, 진행 추정과 최종 완료 판정은 `RA_MVP_PROGRESS.md`에서 확인함.
