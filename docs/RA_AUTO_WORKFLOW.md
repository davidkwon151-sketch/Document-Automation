# 데이터가 있는 RA 담당자의 양식 자동 작성

이 기능의 목적은 기존·신규 원자료를 다시 입력하는 부담을 줄이고, 담당자가 선택한 사내외 양식의 작성 대상 칸을 일괄 기입하는 것임. 기관 제출·전자 접수나 허가 승인을 수행하는 기능은 아님.

## 사용 방법

1. `http://127.0.0.1:8504/`의 첫 탭 **데이터로 자동 작성**을 사용함.
2. 등록된 RA 양식을 선택하거나 자신의 DOCX/HWPX/XLSX/PDF 양식을 첨부함. 처음 쓰는 양식은 실제 입력 위치·값 이름·직접 입력 구분을 확인함. 입력 위치를 해석할 수 없는 PDF 배치는 기존 양식 분석 화면에서 영역을 지정해야 함. HWP 원본은 HWP 자동 변환 탭에서 먼저 HWPX로 변환함.
3. 이번에 완성할 항목과 원자료의 제품명을 선택함. 제형·함량은 실제 원문에 있는 경우에만 입력함. 작성 대상으로 선택한 칸과 원본의 필수 칸을 검사하며, 법정 필수 전체 목록을 추정하지 않음.
4. 실제 원자료를 첨부함. 사진·스캔 전사는 원본과 정확히 대조하여 확인함. 제품명·문맥·파일 SHA·페이지/시트·인용 범위를 보존함. 신청인·서명·동의 등은 담당자가 직접 입력함.
5. **원문 일괄 기입**은 정확한 항목명과 원문 값을 찾아 후보를 함께 확인하고 기입함. 다른 이름의 항목이나 모호한 후보를 자동 추정하지 않음. **실제 AI 작성**은 기존 작성 파이프라인에서 모델로 지시 해석·검색·작성·의미/완결성 검수를 수행함. 실패하면 복사·mock으로 대체하지 않음.
6. 선택 항목 기입률, 부족 자료, 검수 경고를 확인함. AI 초안을 수정하면 다시 검수함. 현재 값과 근거를 확인한 뒤 파일을 만들면 원본 양식 사본과 별도 출처·검수 JSON을 받음. 원본 파일을 덮어쓰지 않음.

화면의 합성 시험 DOCX/CSV는 실제 회사·기관 양식이나 의약품 자료가 아님. 사용자 확인을 전제로 자동 기입을 시험하기 위한 예제임.

## 정확히 구분할 결과

- 원문 일괄 기입 성공과 실제 모델 작성 성공을 구분함. 복사 모드에서는 AI 초안 수정 KPI를 시작하지 않음.
- 이번 선택 항목의 기입률과 원본 전체·미등록칸·법정 첨부의 완료를 구분함. 누락된 선택 항목은 출력 차단 사유임.
- 저장 후 원위치·원본 부품 검수와 실제 Word/한글/Excel의 화면·인쇄 확인을 구분함.
- 최초 표시 AI 초안 기준은 같은 문서의 재생성·입력 보완에도 유지함. 새 문서 시작 또는 다른 양식으로 전환하면 새 기준을 시작함. 실제 직원의 수정률·반려 횟수·업무 시간은 아직 측정하지 않았음.

2026-10-04 실제 연결 점검에서는 JSON 모드의 요청 입력 요구를 수정한 후 HTTP 429 `credit_balance_exhausted`가 반환됨. 현재 실제 AI 작성은 API 잔액 또는 사용 가능한 명시적 로컬 모델 연결이 필요함. 점검한 로컬 기본 포트 11434/1234는 수신하지 않았으며, 이는 모델 설치 여부 전체 조사 결과가 아님. 진단 원시 응답·키는 저장하거나 화면에 노출하지 않음.

JSON 모드 요청은 입력 문맥에 JSON 출력을 명시해야 한다는 [OpenAI 공식 문서](https://developers.openai.com/api/docs/guides/structured-outputs)의 요구와 대조함. 관련 네트워크 없는 회귀 테스트와 실제 API 실패 기록은 별도로 보관함.

## 남은 검증

현재 기본 모델 검색은 제한된 근거 조각을 선정함. 많은 입력칸·긴 첨부에서 모든 필요한 조각을 회수하는지는 별도 평가가 필요하며, 부족한 칸을 성공으로 처리하지 않음. 복잡 PDF 영역·반복 표·새 양식 AI 학습은 기존 전문 화면 `http://127.0.0.1:8501/`의 확인 경로를 사용함.

실제 회사 양식과 비식별 원자료를 사용한 모델 작성, RA 담당자의 수정·최종 확인, 전자 제출 요건 대조가 필요함. 규칙/합성/pytest 결과로 완전한 CTD/eCTD·실사용 수정 0%·모든 회사 양식 호환을 주장하지 않음. 현재 감사는 [RA_PRACTICAL_AUDIT.md](RA_PRACTICAL_AUDIT.md), 실행별 증거는 [VALIDATION.md](VALIDATION.md)에 기록함.
