# 글로벌 직무 문서 자동화 1차 범위

2026-10-04 기준으로 견적송장(Proforma Invoice), 상업송장(Commercial Invoice), 포장명세서(Packing List), 해외영업 활동보고 4종을 대표 우선 업무로 구현함. 직원의 실제 사용 빈도 데이터는 없어 사용 빈도 순위를 주장하지 않음.

## 실제 기능

- PDF, DOCX, HWP/HWPX, XLSX, TXT/CSV/TSV, PPTX, PNG/JPEG의 공통 멀티모달 업로드를 연결함. 사진·스캔·수동 전사는 원본과 대조한 확인 기록이 있어야 사용함.
- 실제 원문 `Order No.`·`거래번호`·`주문번호`와 선택 거래를 대조함. 같은 원본의 서로 다른 거래나 파일명·메타데이터만으로 선언한 거래 범위를 승인하지 않음.
- 항목명이 분명한 원문과 CSV의 실제 머리글·행에서 기입 후보를 찾음. 행 번호를 유지하며 복수 위치는 사용자가 선택함. 원문 값, 전체 출처, SHA, 페이지·시트·위치, 문자 범위를 보존함.
- 예제 양식의 품목 행은 1~20행으로 선택함. 사용하지 않은 행은 비워 두고 사용한 행의 일부 필수 항목 누락을 차단함.
- 제공된 수량×단가와 금액, 품목 합계와 총금액, 순중량≤총중량, 날짜·분량·통화·거래조건을 검수함. 계산한 숫자를 대신 기입하거나 통화·단위·환율·지정장소를 추정하지 않음.
- 사용자 확인 뒤 DOCX 기입과 저장 후 원위치·글꼴·표·원본 SHA 독립 검수를 실행하고 출처·검수 JSON을 함께 제공함. 회사의 확인된 DOCX/HWPX/XLSX/PDF/PPTX 매핑도 동일 core에 연결할 수 있으며 해당 양식별 별도 검증이 필요함.

위 네 가지 빈 양식은 프로젝트 제작 예제임. 한국무역협회 또는 기업의 공식 양식을 확보·검증했다고 표시하지 않음. 현재 기능은 확인 원문 복사 기입이며 실제 LLM 작성, 통관 적합성, 계약·서명 승인과 구분함. 상업송장이라는 문서 선택만으로 실제 선적 완료를 확정하지 않음.

## 사용 방법

RA 작업실의 `해외영업·글로벌 문서` 탭을 사용하거나 `.venv\Scripts\python.exe -m streamlit run app/global_workflow_ui.py`로 실행함.

1. 문서와 품목 행 수를 선택하고 실제 원문에 있는 거래번호를 입력함.
2. 자료를 업로드함. 이미지·스캔을 이용하면 읽기 또는 수동 전사 뒤 원본을 대조함.
3. `원자료에서 항목 후보 찾기`를 누름. 원문 위치와 품목 행의 후보를 확인하며 서명·작성자·보고 대상은 실제 값을 직접 입력함.
4. 확인 체크 후 미리보기와 누락·수치·관계 오류를 해결함.
5. `양식 기입 · 저장 후 독립 검수`를 누른 뒤 DOCX와 출처·검수 JSON을 내려받음.

빈 항목별 TXT를 다운로드하면 실제 근거 값을 정리하는 데 사용할 수 있음. `Currency: USD`, `Quantity[1]: 3`, `Quantity Unit[1]: PCS`처럼 명시하며 실제 원문에 없는 값은 만들지 않음. 행 번호가 다른 항목은 다른 값 이름으로 유지함.

## 조사 근거

한국무역협회의 설명은 견적송장과 선적송장을 구분하고 거래 당사자·물품 규격·수량·가격 등의 역할을 설명함. 포장명세서는 포장 단위별 내용·수량·순중량·총중량 등을 담는 문서이며 관세청 설명도 송장과 물품 명세·규격 단위를 대조하도록 안내함. 이 자료를 대표 업무 선정과 기재 항목 설계에 사용함. 국가별 현재 통관 요건 전부를 검사하는 규칙으로 일반화하지 않음.

## 검증과 남은 범위

`tests/test_global_workflows.py`, `tests/test_global_workflow_ui.py`는 실제 API·네트워크 없이 합성 거래 자료로 source 범위·OCR 보류·개인 직접 입력·복수 위치·CSV·수치 오류·원위치 저장 검수·다운로드 무효화를 확인함. 실제 AI 초안 품질·직원의 수정 비율·반려 횟수·사용 빈도는 미측정임.

현재 전용 회귀는 42개 통과함. 같은 출처·거래번호라도 수출자→수입자, 단가→금액, 품목 1→품목 2의 명시 원문 역할을 바꾸는 연결은 차단함. 등록되지 않은 원문 항목·품목 행이나 원문 역할을 확인하지 못한 인용도 기입하지 않음. 다른 원문 항목명을 사용하려면 확인 매핑의 source_labels에 명시해야 함. 회사·당사자명과 기입값은 해당 원문 항목의 전체 값을 보존하며 일부 숫자·회사명 접두사만 연결하지 않음. 모델·mock·직접 입력 출처는 거래 원자료로 승인하지 않음. 공통 멀티모달 확인 지문도 제안·준비·출력마다 대조하여 확인 뒤 원문·페이지·출처가 바뀌면 보류함.

`outputs/global-workflow-6a4c98e5/`에는 네 종류의 합성 원자료, 예제 원본 DOCX, 기입본 DOCX, 출처 JSON, 독립 검수와 실제 Word PDF·PNG를 저장함. 모두 원위치 저장 검수를 통과했으며 네 문서의 실제 Word 출력 4쪽을 육안 확인함. 추가 네이티브 문구 증분 검사는 활동보고 1종 통과, 무역 3종은 짧은 숫자·공통 단어 20개가 미평가 분모로 남아 경고 상태임. 총 선택 칸 48개 중 28개를 추가 문구 검사했고 실패 칸은 0개임. 이를 모든 입력칸의 네이티브 검증 완료로 표시하지 않음.

거래 ERP의 다양한 실제 열 이름, 승인된 다중 품목 인보이스의 국가별 요건, 이메일·음성·동영상, 정부 지원사업 정산과 계약 검토의 전문 요건은 추가 검증 대상임. 등록·확인되지 않은 신규 회사 양식은 기존 양식 학습 화면의 위치·제약 확인 뒤 연결해야 함. 시각 검수 결과는 저장 후 구조 검수와 별도로 남김.
