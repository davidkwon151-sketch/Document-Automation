# RA 문서 작업실: 실제 효용 점검과 사용법

최신 보완은 [데이터로 자동 작성](RA_AUTO_WORKFLOW.md)과 [독립 업무 감사](RA_PRACTICAL_AUDIT.md), [검증 기록](VALIDATION.md)에 기록함. 이 문서 아래의 작업실 구성·수치는 앞선 원문 기입/변경 비교 버전의 기록임. 새 첫 탭에서 자기 양식과 실제 자료를 연결하지만 실제 모델 품질·직원 KPI는 계속 미측정임.

2026-10-04 기준임. 최신 화면은 <http://127.0.0.1:8504/>임.

## 현재 판정

기존 프로젝트는 양식 보존과 출처·수치 오류 방어를 많이 구현했지만, RA 담당자가 칸마다 자료를 찾아 인용을 확인해야 했음. 이것만으로 RA 업무 시간을 줄이거나 필수 도구 수준이라고 평가할 수 없었음. 사용자 지적에 따라 양식 수 확대보다 근거 선정·비교·인계 부담을 줄이는 기능을 추가함.

현재 버전은 **원문 기반 자동 제안·변경 비교·기입·검수·작업 패키지** 시험 도구임. 일반 AI 작성 파이프라인과 로컬 백엔드는 별도로 구현되어 있으나 실제 RA 모델 생성 성공과 직원 수정률 관측은 0건임. 근거가 없는 CTD·임상·안전성 결과나 변경 사유를 만들어 완성본처럼 표시하지 않음.

## 지금 사용할 수 있는 흐름

1. `공식 양식 기입·작업 패키지`에서 품목허가·변경·갱신 등 업무와 원문 제품명·제형/함량을 선택함.
2. PDF/DOCX/HWPX/HWP/XLSX/TXT/CSV/TSV 원자료를 첨부함. 원문 파일 SHA와 페이지·시트·문단 위치를 기록함. 암호·추출 권한 제한·미확인 OCR 자료는 우회하지 않음.
3. `첨부자료에서 기입 후보 찾기`를 누름. 정확한 같은 항목명과 제품 범위에 후보가 하나일 때만 제안함. 여러 위치·다른 제품·불명확한 범위는 자동 선택하지 않음. 회사 역할은 직접 원문을 확인함.
4. 후보 항목을 선택하고 전체 원문을 확인한 뒤 `확인한 후보를 함께 적용`을 누름. 신청인·서명·승인 등은 직접 입력함. 후보가 없으면 칸별 검색과 원문 인용을 사용함. 첫 40개 뒤의 첨부 조각도 모두 선택할 수 있음.
5. 제품·출처·수치·필수 항목 검수 후 기입값을 확인함. 양식 사본에 저장한 뒤 원래 입력 위치와 원본 서식을 별도로 검사함.
6. 문서·출처 JSON을 받거나, 문서/근거/기입 현황/첨부 확인 기록을 묶은 ZIP을 받음. 등록 입력칸의 기입·미기입 분모와 미확인 첨부를 확인함. 등록 밖의 칸과 법정 제출 요건은 자동 완료로 처리하지 않음.

정형 CSV/TSV는 `제품명,항목,값` 열을 사용함. 항목은 양식에 등록된 정확한 원문 항목명, 값은 실제 근거 원문이어야 함. 행별로 제품명을 함께 유지함. 임의로 정리한 파일의 출처 기록을 공식 허가·임상 결과나 원래 공개자료의 출처로 바꿔 표시하지 않음. 자유 문장의 의미를 추론해 모든 칸에 작성하는 기능과 구분함.

비어 있는 입력 틀은 [일괄 기입 CSV](../samples/ra_workflow_input_blank.csv)와 [변경 비교 TXT](../samples/ra_change_input_blank.txt)를 제공함. 사실·수치·신원 시험값은 넣지 않았으며 실제 원자료로 채운 뒤 사용함. 변경 비교는 전/후 두 파일을 따로 저장하고 제품명·제형/함량·실제 버전을 확인함.

`변경 전후 대비표`는 양측 파일에 명시된 제품명·제형/함량과 정확한 항목을 대조함. 자동 비교는 `항목명: 값` 줄을 대상으로 함. 다음 줄에 이어진 장문·중복 후보는 정확한 전체 인용을 지정하고 확인함. 현재 이 대비표는 확인 대기 CSV/JSON이며 공식 변경 신청서의 변경 사유까지 자동 완결하는 기능은 아님.

`HWP 자동 변환`은 설치된 한글과 실제 활성화된 공식 보안 모듈을 사용함. 이 PC에서는 RA 원본 고유3종→HWPX, 원본/변환본 한글 PDF 총5쪽 배치를 대조함. 원본은 덮어쓰지 않으며 보호를 해제하지 않음.

## 실제 RA 업무 기준으로 남은 핵심 기능

식약처 [eCTD 설명회 자료](https://staticnedrug.mfds.go.kr/resources/26%EB%85%84%20eCTD%20v4.0%20%EC%84%A4%EB%AA%85%ED%9A%8C%EC%9E%90%EB%A3%8C%28260518%29.pdf), [품목 갱신 안내서](https://mfds.go.kr/brd/m_1060/view.do?seq=15962), [시판 후 개별 사례 보고 안내서](https://mfds.go.kr/brd/m_1060/view.do?seq=15967)와 구현을 대조함. 아래는 개발 우선순위이며 모든 최신 법정 요건이나 실제 사용 빈도 순위의 조사 결과가 아님.

1. **변경허가 한 업무 완결:** 이전 허가자료·변경 제안·실제 변경 사유·첨부를 연결하고 공식3행 대비표로 기입함. 현재 비교 CSV를 공식 신청서 완료로 표시하지 않음.
2. **기관 보완답변 추적:** 요청 번호별 원문→답변→근거 파일/CTD 절/페이지→부족자료→담당자를 연결함. 현재 일반 보완질문 입력 기능은 이 기능을 대신하지 않음.
3. **갱신 다자료 대조:** 기간별 품질·안전성·실적·외국 사용·제조원·표시 자료를 묶고 첨부의 실제 내용과 적용 요건을 확인함. 현재 인쇄 안내의 담당자 체크는 파일 내용 자동 검증이 아님.
4. **CTD/eCTD·안전성 전문 업무:** 제출 문서 생애주기/폴더/XML/체크섬 및 ICSR 추적·중복·기준일·기한·전문 검토는 전용 구현/평가가 필요함. 일부 숫자 규칙 통과로 이를 대신하지 않음.

필수 도구 수준을 판정하려면 실제 담당자와 대표 업무3건 이상에서 같은 원자료의 수작업/프로그램 작업을 비교해야 함. 최초 AI 초안 기준을 고정하고 수치·근거·요청 반영 오류와 사용자 수정 비율, 초안→최종 시간, 실제 반려·재작업을 기록함. 작성 모델의 실제 추론과 사람 검토 없이 수정0%·시간 절감률을 보고하지 않음.
