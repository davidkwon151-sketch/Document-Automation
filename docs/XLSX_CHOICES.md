# XLSX 목록 선택 입력

기존 XLSX의 데이터 유효성 목록을 실제 원본에서 읽어 선택 입력칸으로 등록함. Excel 수식 계산 엔진을 구현하거나 원본의 보호 설정을 해제하지 않음.

## 지원 범위

- SpreadsheetML `dataValidation type="list"`와 Office 2010 `x14:dataValidation`의 `formula1`·`sqref`를 읽음.
- `"승인,반려"` 형태의 인라인 문자열, 같은 시트/다른 시트의 한정된 A1 범위, 통합문서 또는 현재 시트 범위의 이름 정의를 지원함. 시트명의 공백·한글·이스케이프한 작은따옴표를 보존함. 현재 시트 이름 정의가 통합문서 이름 정의보다 우선함.
- 단일 대상 셀의 직접 상대 범위는 읽을 수 있으나 여러 대상 셀에 적용한 상대 범위와 상대 이름 정의는 기준 위치가 달라질 수 있어 보류함. 절대 참조 범위를 사용하거나 원본 프로그램에서 확인해야 함.
- 목록 원문은 2048셀 이내 한 행 또는 한 열로 한정함. 적용 범위의 새 입력칸 자동 탐색도 시트당 2048셀까지 한정함. 큰 범위는 확장하지 않고 실제 XML 셀의 규칙을 확인함.
- 값은 XML 문자열에서 읽음. 숫자 `0`과 긴 식별자의 마지막 자리를 부동소수점 변환으로 잃지 않음. 논리값은 `TRUE`·`FALSE`로 구분함. 중복 선택값은 처음 나온 순서를 유지하여 하나로 표시함. 빈 목록값은 선택하지 않은 상태와 구분할 수 없어 제외함.
- 수식 셀, 이미 값이 있는 셀, 병합의 시작 칸이 아닌 셀 및 보호된 시트는 입력칸에서 제외함. 실제 `<c>`가 없는 빈 목록 칸도 한정 범위에서 발견함. 새 셀은 원본의 명시된 행 서식 또는 열 서식만 상속함. 인접 셀의 서식을 임의로 복사하지 않음.

## 입력·검수 계약

프로파일의 선택 입력칸은 `control_type: "choice"`, `options: list[str]`, `choice_items: [{value, label}]`, `input_required: true`, `narrative_style_required: false`를 가짐. `value`와 `label`은 동일한 원본 문자열임. `xlsx_list`에는 적용 주소 `sqref`, 원문 `formula1`, 해당 유효성 XML의 SHA-256을 저장함. 등록된 프로파일도 같은 원본 메타데이터를 가져야 함. 원본의 여러 줄 항목명과 위치는 보존하고 새로 제안하는 `value_key`의 공백만 정규화함. 기존 등록 프로파일의 이름과 사용자가 확인한 매핑은 변경하지 않으며 동일 키에 상충하는 목록은 거부함.

기입 전에 프로파일의 주소·목록 원문·해시·전체 선택값을 현재 원본과 대조함. 프로파일에서 선택 규칙을 일반 텍스트로 바꾸어도 원본의 규칙을 우회할 수 없음. 확인된 목록에 없는 값은 파일을 저장하기 전에 차단함. 선택값은 숫자처럼 보여도 정확한 문자열로 저장함.

저장 후 `verify_output`은 결과물을 다시 읽어 같은 원본 입력 위치의 값과 문자열 타입을 검사함. 원본 데이터 유효성, 이름 정의, 수식, 병합, 행·열 속성, 스타일 및 ZIP 자산을 유지해야 함. 새 셀 예외는 원본에 목록이 선언된 빈 위치에만 적용함. 새 셀/행의 좌표·타입·상속 서식·삽입 순서를 먼저 확인한 뒤 구조 비교에서 해당 셀만 제외함. 다른 새 셀, 원래 셀 손실 및 행 속성 변경은 차단함.

## 자동 입력을 보류하는 경우

외부 통합문서, `INDIRECT`·`OFFSET` 등의 동적 함수, 수식으로 계산한 목록 값, 전체 열/행을 참조하는 목록 원문, 여러 영역을 합친 목록 원문, 없는 시트/이름, 모호한 중복 이름·겹친 유효성은 `choice_unresolved`로 표시함. `unsupported_reason`과 프로파일 경고에 사유를 기록하며 임의 텍스트로 입력하지 않음. 이름 정의의 간접 연결·계산 결과를 추정하지 않음.

선택값 앞뒤 공백은 원문에서 삭제하지 않음. 현재 공통 입력 규칙에서 이런 옵션을 허용하지 않으므로 해당 목록을 미확인 입력으로 보류함. 목록 외의 입력칸에 대한 승인·사용자 확인 절차는 그대로 적용함. Excel 화면의 표시 문자열, 사용자 지정 표시 서식 및 실제 재계산 결과를 이 XML 검사만으로 인증하지 않음.

## 확인 결과

새 목록 회귀 44개와 기존 숫자 셀 회귀를 합친 마지막 집중 테스트 71개가 통과함. 직전 양식·독립 출력·입력 규칙을 포함한 7개 모듈 실행에서는 394개가 통과했으며, 그 뒤 추가한 상대 참조 회귀는 마지막 실행으로 확인함. 인라인/이름 범위/다른 시트/x14·숫자 식별자·논리값·미지원 목록·위조 프로파일·새 셀 서식/행/순서·다중 줄 항목명/키 충돌 및 독립 검수의 고의 변조를 포함함. 새 회귀는 네트워크와 Excel 실행 없이 원본 ZIP 기반 시험 양식을 사용함. 전체 프로젝트 회귀 결과와 구분함.

실제 공개 원본 4개를 검사한 기록은 [native-choice-qa/report.json](../outputs/native-choice-qa/report.json)에 저장함. 목록 해석 수, 빈 선택 입력칸 발견 수, 실제 기입 성공 수와 보호/미지원 사유를 구분함. 원본 SHA 불변을 확인함. 실제 Excel 재계산과 원본 프로그램의 시각 검수는 수행하지 않았으며 JSON에 별도로 보류 표시함.

| 실제 원본 | 목록 규칙/해석 가능 | 발견한 빈 선택칸 | 미확인 빈 선택칸 | 대표 1칸 기입·독립 검수 |
| --- | --- | --- | --- | --- |
| KOTRA 중고차 지원사업 | 8 / 8 | 500 | 0 | D2 통과 |
| 스마트공장 예산 양식 | 7 / 6 | 0 | 0 | 시트 보호로 보류 |
| 정부 공개 서비스 의뢰서 묶음 | 21 / 21 | 9 | 0 | sheet7 M20 통과 |
| 한국성장금융 제안 양식 | 73 / 69 | 38 | 172 | sheet1 G388 통과 |

해석 가능 규칙에는 보호된 시트의 규칙도 포함되지만 입력칸 수에서는 제외함. 기입 가능한 원본 3개에서 각각 1칸씩 시험함. 시험 선택값은 원본 목록에서 고른 합성 입력이며 실제 업무의 승인·신청 결과가 아님. 발견된 모든 칸의 작성이나 네이티브 드롭다운 조작을 검증한 결과로 표시하지 않음. read-only openpyxl 모델의 x14/그림 확장 경고와 원문 ZIP의 부품 손실은 구분함. 기입 엔진은 원문 ZIP을 유지하고 독립 검수에서 확장·수식·자산 보존을 확인함.

## 공식 자료

- [Microsoft SpreadsheetML DataValidation](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.datavalidation?view=openxml-2.20.0): 목록 수식과 적용 참조 범위의 구조를 확인함.
- [Microsoft Office 2010 DataValidation](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.office2010.excel.datavalidation?view=openxml-3.0.1): x14 목록 수식 및 `xm:sqref` 구조를 확인함.
- [Microsoft DefinedName](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.definedname?view=openxml-3.0.1): 통합문서와 `localSheetId` 범위의 이름 정의를 확인함.
