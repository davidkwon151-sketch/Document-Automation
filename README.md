# 문서 표준화 AI AGENT

자료를 근거로 사내외 양식에 맞는 문서를 작성하는 **문서 표준화 AI AGENT** 프로젝트임. 실제 지원·검증 상태는 개별 양식과 검증 기록에 표시함.

**개인 Claude 구독 연결:** 공유 작업실의 `Claude 구독 연결`에서 본인 작업실 전용 키를 발급하고 Claude custom connector에 `/claude-mcp` 주소와 Authorization 헤더를 등록함. Claude 대화가 작성·판독·검수 응답을 만들고 기존 서버가 출처·수치·양식 기입을 검사함. 이 경로는 서버 유료 API를 호출하지 않으며 웹사이트의 서버 API 버튼과 구분함. [연결·작성 순서](docs/CLAUDE_MCP.md)에 이어쓰기·수정 초안 재검수·담당자 확인·키 폐기와 운영 한계를 기록함.

**기본 Gemini 연결:** 외부 작업실에서 각 사용자가 Google AI Studio의 Gemini API 키를 입력해 AI 작성·사진 읽기·재검수를 실행함. 키는 요청에만 사용하며 작업 기록에 저장하지 않음. 서버의 `GEMINI_API_KEY`는 필요하지 않음. Gemini 앱 구독과 Gemini API 키·사용 한도는 별개임. 실제 모델 응답 품질은 사용자 키로 별도 확인해야 함.

**외부 시험 작업실:** [문서 작성 작업실](https://ra-document-workspace-20261004.sooyeon-jun-0389.chatgpt.site/workspace)에서 양식·원자료 업로드, 원문 후보 확인/실제 AI 작성, 출처·수치·누락/저장 후 검수와 문서·출처 ZIP 다운로드를 제공함. 운영자가 발급한 담당자별 초대 링크로 가입 없이 사용하거나 ChatGPT 로그인으로 입장함. 사용자별 자료를 분리하며 별도 인증 Windows 서비스에 HWP 변환을 연결함. 보호된 절 목록 API는 외부 HTTPS 요청으로, 합성 파일의 기입·다운로드와 사용자별 분리는 서버 시험 클라이언트로 각각 확인함. 실제 Claude 계정 등록·Gemini 모델 품질과 실사용 수정 KPI는 별도 확인해야 함. 현재 PC·임시 연결이 실행되는 동안 사용할 수 있는 시험 배포임. 기본 AI 버튼은 사용자 본인의 Gemini API 키와 사용 한도가 필요하며, Claude 연결은 본인 대화의 구독 한도로 처리함. [가입 없는 사용법](docs/RA_NO_SIGNUP_GUIDE.md)과 [운영 방법](docs/EXTERNAL_DEPLOYMENT.md)을 참조함.

**RA 문서 작업실:** `http://127.0.0.1:8504/`에서 공식 양식 기입·변경 전후 대비표·HWP 자동 변환을 사용함. 대표 업무 11종의 등록 입력칸에 대해 첨부 전체에서 명확한 제품·함량·원문 항목의 기입 후보를 제안하고, 담당자가 선택·확인한 후보를 함께 적용함. 복수 후보·불명확한 제품·회사 역할은 자동 결정하지 않음. 저장 후 원래 입력 위치와 원본 서식을 독립 검수하고 문서·출처·작업 현황·첨부 확인 기록을 ZIP으로 묶음. [현재 효용·사용법·검증 한계](docs/RA_USEFULNESS.md)를 먼저 확인함.

**CTD Module 1·3 작업 초안:** 같은 RA 작업실의 `CTD Module 1·3` 탭에서 제품·제형과 절을 선택하고 문서·표·사진/스캔 원자료를 첨부함. 확인된 원문을 절별로 연결하여 출처·누락·모호·보류 목록과 DOCX 작업 초안/근거 JSON을 만듦. 원료 문서는 담당자가 원료–완제 관계를 확인한 경우에만 3.2.S 후보로 연결하며, 절 제목이 없는 자료는 선택형 AI 분류 제안 또는 담당자 출처 선택을 사용함. 보유한 DOCX/HWPX 양식에 `{{3.2.P.5.4}}` 같은 고유 절 자리표시자가 있으면 원서식 사본에 기입하고 독립 검수함. 이 기능의 자동화는 원문 발췌·배치이며 실제 모델이 작성한 CTD, 법정 전체 첨부 또는 eCTD 전자 제출 패키지가 아님. [사용 순서와 범위](docs/CTD_WORKSPACE.md)를 참조함.

**제조원 DMF → CTD 2.3.S:** 같은 작업실의 `DMF → CTD 2.3.S` 탭과 외부 작업실에서 DMF의 확인된 3.2.S.1~7 원문을 2.3.S.1~7 입력칸에 자동 기입함. 원료명·제조원은 원문에 실제 선언되어야 하고 담당자가 선택 완제와의 관계를 확인해야 함. 여러 문서·PDF·표·확인된 사진/스캔을 함께 첨부할 수 있으며 출처 SHA·페이지·정확한 인용과 미기입 절을 별도 기록함. DOCX/HWPX 자체 양식 또는 프로젝트 예제 양식을 사용함. 원문 발췌 기반 검토용 초안이며 실제 LLM 품질요약 생성·허가 제출 적합성 판정이 아님. [사용 순서와 제한](docs/CTD_QOS_DMF.md)을 참조함.

**직무별 작업실:** RA와 해외영업·해외사업개발은 서로 다른 작업실임. RA 작업실에는 공식 변경 기입과 CTD/DMF를 유지함. [해외영업 작업실](https://ra-document-workspace-20261004.sooyeon-jun-0389.chatgpt.site/sales)에는 바이어·파트너 이메일/EML, 회사 원자료 업로드, 요청별 출처 확인, Gemini 회신 초안, 견적송장·상업송장·포장명세서 예제 기입·검수·DOCX 다운로드를 연결함. 회신 초안은 자동 발송하지 않음. 사진·스캔 전사/OCR은 원본 대조 확인 뒤에만 근거로 사용함. 외부 시험 작업실은 현재 PC 연결이 실행 중이어야 하며, 실제 Gemini 응답 품질·담당자 수정률은 미검증임. 로컬 전용 화면은 `python -m streamlit run app/sales_app.py --server.port 8505`로 실행함. [기존 글로벌 기입 사용 순서](docs/RA_GLOBAL_AUTOMATION.md)에 모델 없이 가능한 원문 기입과 모델이 필요한 이미지 읽기를 구분함.

첫 탭 **데이터로 자동 작성**에서 기존·신규 원자료와 등록/업로드한 DOCX·HWPX·XLSX·PDF 양식을 연결함. 이번에 작성할 칸을 선택하여 원문 일괄 기입하거나 실제 AI 작성을 실행하며, 선택 항목 누락·제품/수치/출처 오류와 저장 후 원위치 검수에 따라 출력을 차단함. 원문 기입은 API 없이 사용할 수 있음. 실제 AI 작성은 모델 연결이 필요하며 현재 유료 API 잔액 부족으로 실생성 평가는 대기임. [새 사용법](docs/RA_AUTO_WORKFLOW.md)과 [업무 관점 감사](docs/RA_PRACTICAL_AUDIT.md)를 참조함.

실제 RA 담당자의 시간 절감·수정 비율과 실제 LLM 초안 품질은 아직 입증되지 않음. 공식 원본 11종·선정 입력칸 284개는 재사용 범위이며 모든 CTD 자료·보완답변·서명·필수 첨부·전자 제출을 완결한 수가 아님.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m streamlit run app/ra_workflow_ui.py --server.address 127.0.0.1 --server.port 8504 --server.headless true --server.fileWatcherType none
```

`http://127.0.0.1:8503/`의 **HWP → HWPX 자동 변환**에서 한글 네이티브 변환 기능을 제공함. 원본 보호 검사·읽기 전용 사본·소유 프로세스 확인·변환 후 검증을 거치며 원본을 덮어쓰지 않음. 2026-10-04 이 PC의 공식 보안 모듈 실제 활성화와 RA 대표 HWP 3종 변환을 확인함. 원본/변환본의 한글 PDF 출력 총5쪽에서 크기·텍스트·렌더 픽셀이 동일함. 다른 환경/양식·보호 문서는 별도 확인함.

**RA 최소 시험 화면:** `./start_ra_mvp.ps1` 실행 후 `http://127.0.0.1:8502/`에서 대표 공개 원본6종·작성 설정8개를 사용함. 품목허가·갱신·변경허가·시료 제출·임상시험계획 신청·정기 안전성정보 보고를 연결하며 별지23/32의 앞·뒤쪽 설정에 새4칸을 추가함. API 없는 선정 원문 기입 데모와 실제 AI 작성을 구분함. [빠른 시작·작성 범위](docs/RA_MVP.md), [앞·뒤쪽 범위](docs/RA_SECOND_PAGE.md), [최신 검증](docs/VALIDATION.md)에 실행과 제한 사항을 기록함. 기존 확장 화면(8501)의 `RA 내부 검토 예제`에서 [내부 보고서·변경 기안 DOCX/HWPX 예제](docs/RA_PRESETS.md)로 새 문서를 시작할 수 있음.

첨부 자료와 사용자의 직접 입력을 근거로 보고서·기안과 사내외 양식 문서 초안을 작성함. 신청서·제출서류·계획서·제안서·공문·안내문·회의록·기타 문서 종류를 선택할 수 있음. 원본 문서의 입력칸·자리표시자·PDF 작성 영역을 매핑하며 원본을 덮어쓰지 않음. 최종 출력과 출처·검수·KPI 기록을 함께 보관함.

RA 공개 자료 검증을 확대해 Novo Nordisk·Eli Lilly의 EMA 제품정보 2종을 추가함. 화면의 `글로벌 기업 공식 제출 양식` 목록에서 Pace 시험 의뢰 2종과 Cambrex 시험 의뢰 1종을 가져오면 `의약품·제약 RA → 시험 의뢰·품질자료 지원`으로 연결됨. 새 양식은 원본의 확인된 14칸만 등록했으며 연락처·서명·실제 시험 의뢰 정보는 직접 확인해야 함. [원자료 범위](docs/RA_EXTENDED_PUBLIC_SOURCES.md)와 [기업 양식 검증](docs/RA_EXTENDED_PUBLIC_TEMPLATES.md)에 출처·버전·미확인 항목을 기록함.

## 실행

Python 3.11을 사용함. 현재 작업 공간의 `.venv`는 공식 Python 3.11.9로 구성되어 있으며 `.runtime/python311` 런타임이 필요함. 다른 환경에서는 설치된 Python 3.11로 가상환경을 다시 생성함.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

기본 공급자는 Gemini이며 로컬 실행에서는 `.env`의 `GEMINI_API_KEY`를 사용할 수 있음. 외부 공유 작업실은 서버 키 대신 방문자가 작업 화면에 입력한 본인 키를 요청마다 사용함. OpenAI 모드는 `LLM_PROVIDER=openai`와 `OPENAI_API_KEY`로 별도 선택할 수 있음. API 잔액 없이 실제 AI를 사용하려면 `LLM_PROVIDER=local`과 설치한 작성/임베딩 모델을 설정함. [로컬 AI 실행 안내](docs/LOCAL_AI.md)와 [설정 예시](config/local.env.example)에 Ollama 설치·모델·주소를 기록함. 현재 로컬 런타임 설치/실제 추론은 미검증임. 모든 생성·임베딩·이미지 읽기 호출은 `llm/client.py`를 통하며 타임아웃·재시도·토큰 사용량 로그를 적용함. 키와 원문은 로그에 남기지 않음.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest -q
.\.venv\Scripts\python.exe -m streamlit run app/ui.py --server.address 127.0.0.1
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Streamlit은 `http://127.0.0.1:8501`, FastAPI 상태 확인은 `http://127.0.0.1:8000/health`임. pytest·mock 평가·RA 공개자료 데모는 API 키 없이 실행함. 실제 초안 작성에는 선택한 공급자의 모델 연결 또는 준비된 로컬 서버/모델이 필요함. local 실패 시 유료 API나 mock으로 자동 대체하지 않음.

## 사용 흐름

1. 문서 종류와 업무 분야, 지시와 근거 자료를 입력하고 회사·기관의 원본 양식을 업로드하거나 공개 양식을 선택함. 양식이 없으면 일반 검토용 DOCX/HWPX를 사용함. 보고서 외 문서는 중립적인 사내외 문서 양식을 사용하며 기관 공식 양식으로 인증하지 않음.
2. 입력칸 매핑에서 제목·요약·본문 또는 임의 항목명, 필수 여부, 직접 입력 여부, 분량 제한을 확인함. 처음 보는 양식은 AI 분석을 실행하고 제안한 입력 위치를 확인·저장함. 같은 원본 해시의 확인된 매핑은 다음에 모델 호출 없이 재사용함. PDF는 원본 미리보기에서 작성 영역을 지정할 수 있음.
3. 작성자·개인정보·투표·승인 등 사용자가 결정할 항목을 직접 입력함. 부족한 정보는 한 번에 최대 2개 질문으로 확인함.
4. 자료 검색 → 초안 → 수치·출처·문체 검수 → 상사 예상 질문 → 의미·완결성 검수를 진행함. 원래 지시와 실제 보완 답변도 대조해 누락된 요청을 찾음. 출처 없는 주장, 목표를 실적으로 바꾼 주장, 검수 누락과 오래된 검수 결과를 차단함.
5. 수정본을 저장하고 다시 검수함. 이미지에서 읽은 자료는 원본 미리보기와 대조한 후 확인을 기록함.

처음 보는 PDF의 이미지 분석 쪽 수는 실제 전체 페이지까지 선택할 수 있음. 일부만 선택하면 분석한 쪽·남은 쪽을 표시함. 코드에서는 `learn_template(..., max_image_pages=None)`으로 전체 페이지를 분석함. 많은 입력칸은 64개씩 분석하며 다른 배치의 ID·누락·중복·반복 항목 제약 충돌을 검사함. 페이지 분석 실패를 부분 완료로 저장하지 않음.

DOCX/HWPX에서 품목·참여자 등 작성 행을 늘리려면 `반복 표의 행 수 조정`을 사용함. 빈 원본 행과 작성할 행 수(원본 포함 1~200)를 선택하면 원본과 다른 준비본을 만들고 행마다 입력값을 구분함. 원본 등록 규칙과 확인 매핑을 승계하고 준비본·기입본을 각각 검수함. 명시적 자리표시자는 선택한 작성 행마다 채워야 하며, 빈 셀의 업무상 필수 조건은 사용자가 지정함. [사용법과 검증 범위](docs/REPEAT_ROWS.md)에 지원 구조·보류 조건을 기록함.

6. 최종 내용을 확인한 뒤 DOCX/HWPX/XLSX/PDF/PPTX와 출처 기록을 내려받음. 저장 파일을 독립적으로 다시 열어 정확한 입력 위치·주변 안내문·줄바꿈·서식 부품을 대조함. 양식에 출처 ID를 인쇄하기 어려우면 별도 출처 기록 방식을 선택함.

다운로드 영역에서 실제 Word·Excel·PowerPoint 출력 확인과 전체 쪽 미리보기를 제공함. 명확한 입력 누락·숨김·인쇄 영역 제외는 차단하고 미확인 범위는 표시함. 모든 형식의 확인이 끝나야 다운로드하도록 선택할 수 있음. [사용 방법·검수 범위·RA 평가 명령](docs/NATIVE_OUTPUT_REVIEW.md)에 자동/필수/미사용 모드를 기록함.

`새 보고서 시작`을 누르기 전까지 자료 보완·재생성에도 같은 최초 초안 KPI를 유지함. 저장한 보고서는 원자료·보완 답변과 함께 이어서 검토할 수 있음. 새 첨부 자료는 저장 자료와 함께 반영하며, 기존 자료를 제외하려면 해제 버튼을 사용함.

DOCX/HWPX/HWP의 물리적 페이지는 추정하지 않고 실제 원문 경로를 기록함. 계산 캐시가 없는 XLSX 수식은 원자료 수치로 사용하지 않음. 고정 높이 DOCX 셀과 XLSX 줄바꿈·병합 셀의 명백한 넘침을 검사함. 실제 전체 페이지 재배치·자동 행 높이·회전 글자·PPTX 장문·한글 프로그램의 HWPX 배치는 별도 확인 대상임. PDF 영역에 넘치는 내용을 잘라내어 저장하지 않음.

본 제품은 한컴의 HWP 문서 파일(.hwp) 공개 문서를 참고하여 개발하였습니다.

DOCX의 양식 작성 보호는 유지한 채 활성 FORMTEXT 입력 결과만 작성함. 명확한 업무 설명·사양은 원자료를 근거로 채울 수 있고, 이름·서명·동의·승인·모호한 항목은 직접 입력함. 보호된 일반 본문이나 비활성 입력칸을 수정하지 않음.

DOCX 드롭다운·콤보와 XLSX의 지원되는 선택 목록은 원본 허용값을 유지함. 화면에서 사용자가 선택하며 표시 이름과 저장 코드가 달라도 정확히 전달함. 반복 표의 사용한 행에는 선언된 필수 칸을 요구하고 미사용 행은 비워 둠. 잘못된 직접 입력은 모델 호출 전에 검사함. [선택 목록·행 완결성 검증](docs/NATIVE_CHOICES_AND_ROWS.md)에 지원 범위와 실제 원본 검증을 기록함.

PDF의 단일 선택·직접 입력 가능한 콤보·다중 선택 목록도 원본 권한에 맞춰 작성함. 다중 선택은 화면에서 항목을 골라 입력하며 저장 코드와 표시 문구를 구분해 원위치·표시·선택 강조까지 독립 검사함. 비워 둔 선택칸은 원래 값을 유지함. [PDF 선택 목록 보강](docs/PDF_NATIVE_CHOICES.md)에 구현과 실물 검증 범위를 기록함.

DOCX·HWPX·XLSX는 확인한 빈 행을 원본 포함 1~200행으로 확장하고 원본 규칙·행별 매핑을 승계함. [XLSX 반복 행](docs/REPEAT_XLSX.md)은 삽입에 따른 참조 이동과 복제 수식의 상대 복사를 구분하며 합계·다른 시트·인쇄 범위를 이중 검수함. 실제 Excel에서 공개 신청서 2종과 합성 RA 비용 양식의 선택 범위를 확인함. 원본부터 여러 쪽으로 나뉘는 인쇄 설정과 행 추가 후 페이지 증가는 별도 주의 사항임.

## KPI와 품질 평가

핵심 KPI는 최초 표시 AI 초안 대비 최종본의 수정 비율임. 항목별 문자 삽입·삭제·치환 수의 합을 각 항목의 비교 문자 길이 합으로 나눔. NFC·줄바꿈·줄 끝 공백을 정규화하며 나머지 공백·문체·출처 변경은 수정에 포함함. 큰 차이는 제한된 블록 근사 계산임을 표시함.

초안 표시 시각부터 최종 확정까지의 시간과 사용자가 실제 기록한 상사 반려·재작업 횟수도 저장함. AI 예상 질문이나 자동 수정은 상사 반려로 세지 않음. 재생성·반려 후에도 최초 기준을 보존함. 재작성 중인 보고서는 확정 보고서 KPI 중앙값에서 제외함. 확정 기록이 없으면 수정 비율을 0%로 표시하지 않음.

사용자가 명시적으로 저장한 안전한 동의 표현만 다음 초안에 적용함. 수정된 숫자·회사명·개인명·본문을 선호 설정으로 학습하지 않음. [Zapier의 2026년 조사](https://zapier.com/blog/ai-workslop/)가 보고한 주당 약 4.5시간의 AI 결과물 재검토 부담을 고려해, 테스트 점수와 실제 사용자 수정 부담을 별도로 측정함.

초안 생성·AI 내부 검수 시간은 사용자 최초 초안→확정 시간과 별도로 표시함. 새 양식 학습은 확인한 매핑·제약을 재사용하는 방식이며 모델 가중치 학습은 아님. 매핑 캐시에는 개인 입력값·본문·보완 답변을 저장하지 않음.

`evals/cases.json`은 지시·첨부 자료·기대 기준 15건을 포함함. 양식 준수·유효 출처 포함률·수치 정확도·문체 준수를 점수로 계산함. 부족한 정보 사례는 초안 점수의 분모에서 제외함. mock 점수는 연결·검증 회귀 결과이며 실제 모델 정확도나 수정 0%를 뜻하지 않음. 실제 모델 평가는 프롬프트·첨부자료 해시·모델명을 기록하고 같은 평가셋끼리 점수 하락을 비교함.

`evals/domain_cases.json`은 RA·무역/지원사업·기획/금융 각 8건, 총 24건의 정상·오류 초안 회귀를 포함함. `rules`는 원자료와 고정 초안을 대조하며, `live`는 정상 사례 12건에 실제 모델을 적용함. 응답 획득 수·모델 설정·프롬프트 해시를 기록하고 API 실패를 실제 모델 평가 완료로 표시하지 않음.

`evals/ra_public_sources.json`은 삼성바이오에피스·셀트리온 계열사·UCB의 공식 EMA 원본 3종과 선택 제형의 전체 인용 14개를 포함함. `evals/ra_korean_sources.json`은 한미약품과 과거 인쇄 수입자 한국엠에스디의 제품 설명서 기록임. `evals/ra_additional_sources.json`에 동국제약·종근당의 공식 설명서 2종·선택 사실 9개를 추가함. 허용 원자료 6종 전체 378페이지·127개 표와 28개 고유 선택 사실을 운영 파서로 대조함. 추출 제한이 있는 에리우스는 자동 평가를 보류함.

최신 교차 검증은 6회사 원자료 × 법정 2종·Roche·Eurofins·SGS 5양식의 선택 기입 **30건 통과·보호 5건 보류**, 원문·출처 **74/74**, 수치 포함 필드 **61/61**임. 출력 96쪽을 렌더하고 원래 입력 위치·서식·출처 sidecar를 독립 대조함. 추가 `pdf_copy` 검수는 6통과·24경고이며 실제 LLM 초안·사용자 수정 KPI는 미평가임. 한글 표시·재편집 glyph·회사 역할·입력칸 위치 변조 검사를 보강함. 상세 분모와 재실행 명령은 [최신 RA 회사별 교차 검증](docs/RA_CROSS_COMPANY_VALIDATION.md)에 기록함.

이전 11건·원문/출처 41/41·수치 필드 35/35의 이력은 [앞선 RA 실자료 검증](docs/RA_REAL_SOURCE_VALIDATION.md)에 보존함. 기업 빈 양식 조사·보호 차단·Word 원본 대기는 `evals/ra_corporate_sources.json`에 분리함. 용량·용기·대상·간격·조건·출처 등을 변형한 EMA 오류 92건의 별도 회귀는 `evals.ra_adversarial`로 실행함. 기업 내부 RA 전수나 실제 LLM 생성 정확도의 점수가 아님.

긴 내용은 명시적 별첨 선택으로 원칸 참조와 전체 원문 별첨에 보존함. 공식 RA 프로파일은 출처를 별도 기록하는 설정을 기본으로 사용함. PDF 읽기순서가 달라지면 문자·빈도를 대조하고 두 순서를 기록함. 손실·중복·제어문자 때문에 원래 순서로 돌아간 페이지는 원문 확인 전 다운로드를 차단함. 열람 가능 여부와 추출 권한을 구분하며 보호 제한을 OCR로 우회하지 않음.

이 평가는 기업 내부 비공개 RA 양식 확보나 국내 허가·갱신 제출 적합성 검증이 아님. `rules`의 원문 복사 성공을 LLM 작성 품질이나 사용자 수정 0%로 표시하지 않음. 실제 자료 목록은 [RA 공개 원자료](docs/RA_PUBLIC_SOURCES.md), 검사 결과와 남은 항목은 [검증 기록](docs/VALIDATION.md)에 기록함.

공개 PDF 원본은 Git에 포함하지 않음. 새 작업 환경에서는 manifest의 공식 URL에서 지정된 경로에 원본을 확보하고 SHA를 확인해야 실자료 검사를 실행할 수 있음. 원본 없는 pytest 실자료 항목은 skip으로 표시하며 `evals.ra_public`은 원본 누락·해시 불일치를 실패로 기록함. 이번 환경에는 원본을 확보했으며 에리우스의 추출 제한만 보류함. 보류된 보호 정책 자체는 별도 테스트로 확인함.

## 입력 오류와 RA 조건 이중 검수

숫자·정수·날짜·인쇄 단위와 합계·대소·날짜 관계를 초안/수정본·기입 전·저장 후 검사함. 직접 입력 오류는 항목 아래에 표시하고 미해결 오류의 출력을 차단함. 규칙은 새 양식의 확인 매핑과 함께 재사용하며 합계나 누락 날짜를 임의로 보충하지 않음.

공개 양식 10종의 92개 칸·22개 관계를 등록함. XLSX의 명시된 빈 숫자칸은 실제 숫자 셀로 저장하고 정확한 XML·원본 수식/서식을 대조함. RA에서는 성상 출처·임상 적용/예외·의사 판단·증량 조건을 연결된 원문 조각과 확인함. 이전 입력 보강의 전체 pytest 1,570개 결과는 [검수 보강 보고서](docs/ACCURACY_HARDENING.md)에 보존함. 최신 전체 회귀·RA 11건 선택 기입·선정 변형 오류 92건 및 Excel 재계산의 확인 범위는 [검증 기록](docs/VALIDATION.md)에 기록함. 실제 LLM 정확도와 사용자 수정 KPI는 미평가임.

## 저장과 현재 확인 범위

원자료·초안·수정·검수·출처·KPI 스냅샷은 `data/runs/<run_id>/`, 최종 파일은 그 아래 `outputs/`에 저장함. 선호 설정은 `data/preferences.json`임. 테스트는 임시 디렉터리를 사용함. 로컬 자료를 삭제하려면 UI를 중지한 후 필요한 결과를 보관하고 해당 실행 폴더를 직접 삭제함.

네이티브 Word에서 대표 DOCX 양식과 출력물을 열어 PDF로 렌더링했고 PDF 폼·좌표 출력의 한글·목록·원본 배경을 확인함. Word/Excel을 통한 DOC/RTF/ODT/XLS 변환도 실제 재파싱했음. 자체 PPTX 샘플은 실제 PowerPoint에서 원본·작성본을 PDF로 렌더링해 제목·목록·표와 미변경 슬라이드의 동일한 렌더링을 확인함. 이는 실제 기업 모든 PPTX의 검증 건수로 계산하지 않음.

앞선 실제 API 평가의 크레딧 오류로 실제 LLM·이미지 읽기·실사용 수정 비율·상사 제출 결과는 검증 대기임. 성공 생성응답·사람 KPI 관측은 아직0임. 한글 보안 모듈은 실제 자동화 호스트의 등록·가시성을 해결하여 활성화했고 RA 고유 HWP 원본3종→HWPX 변환과 한글 PDF 총5쪽 배치 대조를 완료함. 모든 HWP의 호환이나 도형 본문 파싱 검증은 아님. 최신 검사 결과와 정확한 분모는 [검증 기록](docs/VALIDATION.md), 처리·학습·검수 구조는 [설계 문서](docs/ARCHITECTURE.md)에 기록함.

개발 상태와 남은 검증은 `PLANS.md`에 기록함. 이 구현은 로컬 사용 도구이며 공용 서버 운영을 위한 로그인·다중 사용자 권한·기관 제출 시스템 연동은 포함하지 않음.
